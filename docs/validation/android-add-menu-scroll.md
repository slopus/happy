# Android 加号菜单滚动与紧凑会话推荐

基线：`6b419f7a85e24b897a81bbbaefb733274c0c873c`。

## 需求与实现

用户反馈 Android 点击输入区「+」后，滑动菜单会穿透到背景，且「对话」区域过高。2026-11-29澄清：首屏只露约两行，默认仍应有最近5–10条可随整个面板滚动。本次采用最近10条；初版误把两行解释为推荐数量上限，已纠正。

原生旧 Host 仅返回 Fragment，菜单由 MessageComposer 的 `bottom: '100%'` 绝对定位绘制到输入框祖先边界之外。`overflow: visible` 允许绘制，却不能扩大 Android 祖先的触摸命中区域；增加滚动属性本身无法解决这一边界。

- Android 的显式「+」入口由平台专用 Host 使用既有 `NativeComposerSelectorSheet` 承载。原生 Modal 阻断背景手势，安全区与键盘避让复用现有实现；内容保持一个有界 ScrollView。
- Android 空查询保留按原有活跃时间排序的最近10条会话，并在总计30项的预算内为会话预留位置，避免插件/站点多时把推荐挤没。`@` 非空查询继续搜索完整已加载会话集合，沿用既有搜索结果上限。
- Android 默认面板高度按前面现有分组加两行会话计算，上限沿用388dp；其余会话与前面分组共用同一个ScrollView。不会增加嵌套会话滚动区；前置分组本身过长或窗口较短时仍受整体高度上限限制。
- `@` 输入仍走原有内联路径，避免 Modal 抢走输入焦点。此次修复范围是显式「+」入口；未重构 `@` 内联浮层的原生命中区域。
- iOS 与 Web 沿用原有 Host 与会话推荐策略。界面主题继续使用现有语义 token；没有新增输入框常驻内容、依赖、权限、原生资源或 runtime 变更。
- 遮罩与 Android 返回键关闭时不主动恢复键盘；选项、文件入口与草稿沿用既有处理。

- 默认两条会话完整可见；选择第二条后菜单关闭、引用 chip 出现、原草稿保留；点击输入仍可继续键入。

# Android 加号菜单滚动与紧凑会话推荐

基线：`6b419f7a85e24b897a81bbbaefb733274c0c873c`。

## 需求与实现

用户反馈 Android 点击输入区「+」后，滑动菜单会穿透到背景，且「对话」推荐过长。要求整个面板可滚动，默认约两条对话。

原生旧 Host 仅返回 Fragment，菜单由 MessageComposer 的 `bottom: '100%'` 绝对定位绘制到输入框祖先边界之外。`overflow: visible` 允许绘制，却不能扩大 Android 祖先的触摸命中区域；增加滚动属性本身无法解决这一边界。

- Android 的显式「+」入口由平台专用 Host 使用既有 `NativeComposerSelectorSheet` 承载。原生 Modal 阻断背景手势，安全区与键盘避让复用现有实现；内容保持一个有界 ScrollView。
- Android 空查询仅推荐按原有活跃时间排序的两条会话。`@` 非空查询继续搜索完整已加载会话集合，沿用既有搜索结果上限。
- `@` 输入仍走原有内联路径，避免 Modal 抢走输入焦点。此次修复范围是显式「+」入口；未重构 `@` 内联浮层的原生命中区域。
- iOS 与 Web 沿用原有 Host 与会话推荐策略。界面主题继续使用现有语义 token；没有新增输入框常驻内容、依赖、权限、原生资源或 runtime 变更。
- 遮罩与 Android 返回键关闭时不主动恢复键盘；选项、文件入口与草稿沿用既有处理。

## 原生证据与边界

旧实现已在独立 API36 模拟器复现：菜单内部连续上滑，菜单仍停留在首项，而背景 offset 从 0 增加到约 277dp。测试执行原始 MessageComposer、Picker、Host 基线字节，而非仅改变 Platform 的组件 mock。

修复版在独立 API36 / 411dp 模拟器中复验通过：

- 同一内部上滑使文件/早期插件移出、后续插件与两条会话进入视野，背景 offset 一直为 0。列表边界继续滑动也保持背景不动。
- 默认两条会话完整可见；选择第二条后菜单关闭、引用 chip 出现、原草稿保留；点击输入仍可继续键入。
- 文件行可衔接真实 AttachmentSourceSheet，显示照片/文件两个来源；系统文件选择与真实文件上传不在本次 fixture 范围。
- 遮罩与 Android Back 可关闭，重新打开可用；进入前键盘关闭时没有额外弹键盘。进入前已有 IME 时，系统返回可恢复原输入状态，不将此计作失败，也未增加主动 blur/dismiss。
- `@` 连续输入仍在原输入框中完成，键盘保持，查询过滤可用。当前已有 `@` 建议时点击加号先按原切换语义关闭建议，再次点击打开显式加号浮层。

fixture 使用合成内容与本地回调，隔离角色/插件读取及未登录前台同步，不涉及生产账号、模型消息或用户数据。完整登录 App、真实系统文件上传、用户手机、iOS、其他分辨率/字体组合未验。独立交互复核已确认滚动、两条完整行、引用/草稿保留、文件来源浮层与键盘/关闭状态，未发现可见 Critical / Important；时序以原生执行日志及录像为准。一张中途误点重试的截图已排除，引用以真正完成选择后的状态为证据。

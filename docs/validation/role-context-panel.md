# 对话内查看角色：保留主流程

来源：用户提供角色保存卡截图，要求“查看角色”右侧打开，并将对话中的辅助内容不影响原对话流程记录为交互原则。原截图中的QA角色已清理，历史快照与当前配置须明确区分。

采用现有SessionView右侧详情/窄屏抽屉宿主，不重做聊天布局、不恢复旧平铺角色管理。原则唯一来源为docs/design/overlay-interaction-standard.md，CLAUDE与设计入口负责导航。

| Case | 通过标准 | 状态 |
| --- | --- | --- |
| C1 | 保存卡点击打开右侧精确角色，不切主对话；当前URL、输入与阅读位置保留 | 候选Web通过 |
| C2 | 关闭/重开恢复原侧栏状态与焦点；消息区持续挂载，进行中的会话不被停止 | 候选Web通过 |
| C3 | 明确编辑在现有设置浮层内完成，退出回原对话；原设置CRUD不退回旧平铺表单 | 候选Web真实RPC通过 |
| C4 | 读取加载/错误/离线和角色已删除有真实状态；已删角色只读历史快照不开放编辑 | 状态回归通过；正式已删快照待复验 |
| C5 | 窄屏复用右侧抽屉，账号/机器变化及迟到响应不串；原生设备结果单列 | 390宽Web通过；owner/迟到回归通过；无原生设备 |

## 实际验证

- 基线9d9d7fff。使用用户指定截图与当前正式保存卡取证；原位复用现有品牌图标、主题和SessionView右侧宿主，没有更换聊天框架。
- C1/C2：1668×908完整App，右栏打开前后URL保持原会话；保存卡纵坐标偏移0，消息列表和输入框为同一DOM节点，验收草稿完全保留。X、全局右栏按钮、Meta+Alt+B、Escape均可关闭并重开，原折叠偏好恢复。实际模型生成20条回答时打开详情，后续回复仍到达且面板保持打开。
- C3：真实角色目录→设置浮层→编辑职责→RPC保存→关闭浮层，一次关闭回原会话，侧栏显示新职责。消息列表/输入框节点和草稿不变，关闭详情后焦点回保存卡。修正了只读详情X被角色Back override拦成回清单的问题；返回箭头与脏稿确认保留各自语义。
- C4：当前机器成功目录才允许进入管理；单测覆盖加载/离线/读取失败/已删除、账户ABA及旧机器响应。历史回执是保存时快照，不冒充仍存在配置，不调用旧平铺角色编辑器。
- C5：390×844下等待响应布局稳定后再记录节点；抽屉宽390且无横向溢出，打开、关闭前后消息列表/输入框节点和草稿相同。首次发现Web受控抽屉等待spring回调导致角色关闭未完成，本轮仅角色详情Web分支直接更新受控关闭，原生保留动画回调；复验通过。跨断点替换布局不作为打开抽屉导致重挂的证据。

## 检查与交付边界

- 全App最终642文件/6124测试通过；完整App类型检查通过（停止本轮Metro后仅移除其生成路由声明与tsbuildinfo，未用pathname cast掩盖错误）。独立非作者评审覆盖右侧接入、owner隔离、关闭入口、设置关闭与Web/native分支，无阻断。
- 最终录像11.866秒、1440×784、H.264/yuv420p/30fps。195个Ego原生帧，实际采样10.822秒、最大间隔320ms，完整解码通过，已Happy发送。录像显示宽屏开关/快捷键及设置浮层往返；持续消息、真实保存与390宽断言由另行实际E2E支持，不声称短片完整覆盖全部过程。
- 仅使用当前服务上的一个本轮QA角色和一个QA会话，原写作助手不修改；正式发布复验后精确清理。无需CLI/server/native/runtime改动，不重启daemon，不新建APK。
- 当前无ADB设备：手机原生触控/键盘/动画与OTA实际加载未验；窄屏Web和原生平台测试不是用户手机验收。正式Web/OTA状态与精确版本归唯一发行记录。

最短复跑：新建专用QA角色并在普通会话产生真实保存卡→填写未发送草稿→查看/关闭/重开→检查原会话URL及草稿→设置浮层编辑保存并关闭→窄屏复跑；只清理本轮对象。自动化入口为RoleDetailPanel、ToolView.roleResult、SessionView.agentSpace、useDesktopWorkspaceLayout、useRoleFlowNavigationBack及DelegationRoleManager相关测试。

# Codex 启动时的 Skill 元数据扫描保护

实际后台 worker 在注册机器后进入同步 Skill 遍历，主线程阻塞于 `readdirSync → scandir → open`，90 秒后上层报启动 webhook 超时。旧运行包和新候选的扫描代码一致；这不是工具事件 mapper 的回归。具体阻塞目录与底层权限原因未确认，不将其归因为已证明的 TCC 或外盘故障。

扫描器现在把含 `SKILL.md` 的目录作为叶子，避免继续遍历技能内部的项目、依赖、状态与符号链接。聚合目录、插件容器、原 Skill 名称和同步 helper 保持兼容。

启动阶段只在隔离 Node 子进程中读取 Skill 名称。默认 2 秒的单次 deadline 独立于 child 的 `close`：到期仅终止本次 scanner，销毁管道并释放引用，然后返回空元数据清单，让主 worker 继续启动。stdout 限制 128KB，非法 JSON、名称或子进程异常也返回空清单。没有周期重试或业务轮询。

这只影响 Paws 的可选 Skill 名称元数据，不修改 Codex 全局配置、文件系统权限或技能本身。操作系统可能延迟响应 SIGKILL；调用方不等待内核完成退出。

目标验证 26 项通过：5 项同步目录扫描、12 项隔离/超时/真实阻塞进程、4 项真实 MJS/CJS 打包入口、5 项原子构建。CLI 完整构建和类型检查通过；独立评审通过。真实后台启动、只读工具与模型完成验收单独记录在发布回执中。

# 委派复审问题修复与验收

本次覆盖历史存储、原生准备配置持久化及 Antigravity 控制工具权限三处已隔离复现的问题。正常委派继续复用现有原生执行器、事件回执和任务快照。

## 验收契约

| 场景 | 要求 | 证据入口 |
| --- | --- | --- |
| 合法历史大于 32 MiB | 已允许保存的任务历史能够重新加载；任务专用读取有明确上限 | `daemon/delegation/store.test.ts` |
| 单个损坏、超限或符号链接记录 | 保留原件、输出可定位的脱敏诊断，其他健康记录仍可加载；失败记录不得被意外覆盖 | `daemon/delegation/store.test.ts` |
| 原生准备配置后 HTTP 回执丢失 | 在发送前持久化实际型号及强度；原生完成、协调器重建及同子会话续修仍保留该配置 | `daemon/delegationRuntime.test.ts`、`daemon/delegation/service.test.ts` |
| 保存准备配置失败或权限/取消状态改变 | 未确认持久化时不得发送业务消息；迟到回执不能改写旧修订配置 | 同上 |
| AGY 原生 Happy 控制工具 | 原生工具身份经规范化后命中既有精确批准策略，保留原生许可选项语义 | `agent/acp/AcpBackend.permissions.test.ts`、`agent/acp/runAcp.test.ts` |
| 其他工具、相似名称、冲突身份或命令伪装 | 保持既有审批边界，不从任意标题或子串升级权限 | 同上 |

## 验证边界

回归使用受控临时存储及 HTTP/native RPC 故障注入，不向正式存储写入超大或损坏记录。正式入口验收从新 AGY 默认权限会话执行限定 Happy 控制工具及同执行器子任务，核对无额外审批、准确结果回流及完成状态；只清理本轮专用对象。

执行端更新保留活动包既有叠层和冻结依赖，保护原有 worker。源码合并、候选验证、实际激活和正式页面使用分别记录；不以构建或单测替代当前设备验收。旧 worker 不会热加载本次更改。

本次为 CLI 运行时修复，不改变 App 原生运行契约。

## 已完成的本地检查

- 独立评审新增的空消息协议回归及坏 ID 隔离修复后，最终 8 个相关文件、280 项回归通过；实际 CLI 构建及依赖/源码类型检查通过。
- ACP 全目录最终执行 11 个文件、194 项回归通过；该范围与上面的检查有重叠，不相加计数。
- 三项缺陷及 SDK 丢失兼容身份字段的路径均先观察到失败，再完成修复。
- 独立评审发现的自定义 transport 空消息兼容问题也已通过真实 wire 回归修复；空消息继续交由 SDK 按既有语义处理。
- 历史压力回归实际读写约 243 MB 的 100 修订记录。256 MiB 是单任务文件读取上限；同步 JSON 解析和多任务累计内存仍有成本，不将它描述为无内存限制。
- 正式生效、当前设备核心操作及专用测试对象清理由交付记录另行核验。

## CI 测试边界补修

首轮 CI 暴露两个测试夹具问题：新建 worker 的初始状态可与审批夹具写入竞争，夹具现只对服务端明确返回且带合法版本的 CAS 冲突重试，最多三次，其他错误立即失败；主线将委派分组拆成独立组件后，公开对话与消息可见性测试需补齐该叶子组件的 mock，避免加载不属于测试目标的原生界面依赖。这些补修不改 App 或 SDK 的生产行为。

工作区 CI 还显式安装 `ripgrep`，以运行现有的真实大文件解析回归；缺失二进制的 fallback 继续由独立用例验证，不放宽或跳过计数及 JSON 解析断言。

# Codex 失效模型选择恢复

## 问题与行为

已有会话的 `modelMode` 是本机持久化覆盖项。过去界面和消息构造都会优先保留它，即使当前账号的 `metadata.models` 已明确不包含该型号；例如保存了 `gpt-6.2-astra`，ChatGPT 连接只支持其他型号，下一轮便被执行端账号校验拒绝。过期的通用默认项也会造成相同问题。

本次由界面与消息构造共用 `resolveSessionModelKey`：仅在 Codex 会话目录非空时，按本地选择、当前会话模型、当前默认项顺序选择目录中存在的型号；都失效则发送明确的原生默认重置。保留内部 `default` 重置语义，不按目录顺序猜型号，不借用另一账号或 Magpie 目录。目录尚未发布时保留明确选择。

推理强度与 Fast 按解析后的模型能力继续计算。执行端的账号/模型校验保留；当前目录仍然可能被上游撤销，客户端过滤不能保证所有上游请求成功。

## 范围

- 沿用已有会话的模型选择器和详情入口；没有新增输入区域内容、控件或样式。
- 仅修复 Codex 已加载目录下的失效选择；其他 Agent 的模型解析不变。
- 不改账号绑定、角色、原生依赖、图标、权限或 runtime；无需重建 APK。
- 既有队列在入队时保存的控制快照保持原契约，不重放已失败的用户业务请求。

## 验证

- 86 项模型目录、界面/消息一致性与消息元数据测试通过。
- 新增 12 项行为回归覆盖失效本地型号、外部网关别名、失效默认项、有效本地选择、全失效原生重置、明确重置、连接实际支持新型号、原生网关目录、目录未到达及恢复后强度/Fast。
- 完整 App TypeScript 检查通过。
- 源码评审确认有效选择不变、目录未知时不重写、原生默认重置明确且账号边界未放宽。

真实页面、发布和用户原客户端的验证结果由本次 Release OPS 唯一发行记录维护；用户尚未提供最初出错会话的链接，不能把本诊断会话当作原故障会话已恢复。

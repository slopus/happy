# Codex ↔ Gemini 同会话验收

本轮从 2026-11-28 接续至 2026-11-29。目标是保留一个产品会话，在 Codex 与 Antigravity/Gemini 之间讨论和执行，并区分真实模型结果、受控协议测试与尚未覆盖的场景。

## 修复范围

- Codex 权限选择等待执行端 RPC 确认；失败或 worker 换代保留原值。该确认不代表正在运行的原生回合能即时撤销沙箱权限。
- 新增独立 `conversation-prepare`：首条业务消息前确认目标原生运行时、模型、推理强度及权限；回执绑定 root/source/request、worker PID 与不可变历史 ID/hash。
- 配置和归属检查持续到原子 outbox 提交。准备失败保留候选和草稿；重试同一候选，投递未知时不自动重放业务请求。
- AGY 使用 fresh native + portable history；未实现原生 AGY resume。Codex 恢复受原生身份及账号证明约束。Claude/OpenCode 保留既有路径。

## 真实基线

环境为正式 Paws Web 与 Mac mini 执行端，使用本轮专属测试目录及合成资料；没有改写用户业务文件。以下已在活动旧 CLI 上验证，不能替代新补丁激活后的回归。

1. Codex 读取约 108 KB 的长文本和约定文件，接收真实图片附件。
2. 同 root 切换 Gemini 4 Neon。Gemini 通过 `thread_read` 读取初始预算外的原文，在约 53 KB 偏移处找到核对码；通过 `thread_attachment` 取得历史图片并正确识别水獭、电脑和黄色背景。
3. Gemini 新增 `review_tag` 与 `enabled=false`。切回 Codex 时提示不重述字段值，Codex 写出的 JSON 与四项约定完全一致；原草稿 SHA-256 未变，也没有生成已否决的 HTML。
4. Codex 请求批准模式下，项目内读取成功；项目外写入触发原生审批，明确拒绝后文件不存在。
5. 刷新同一 root 后旧审批没有复活；只提交一次只读恢复请求，Codex 回复 `RECOVERY_DONE` 并完成。JSON 与草稿保持完整，项目外文件仍不存在。

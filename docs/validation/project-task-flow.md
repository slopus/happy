用户反馈：项目页的“清单”按钮没有可见结果；卡片对话需要重复点击；交付状态混淆约定与验收；缺少目标文件总览；任务目录重复加载。

## 最终行为

- “清单”和“归档”从项目页返回会话工作区，同时选择正确的侧栏模式。
- 卡片正文只选任务；任何卡片的对话按钮均一步打开其最近会话。没有历史才创建空白会话，历史读取失败不创建替代会话。显式新会话仍是独立动作。
- 对话旁保留主线的任务导航，切换任务后可继续原会话，保留清单展开状态及各自未发送草稿。后退/更换任务后拒绝迟到的打开结果。
- 卡片状态区可直接打开交付编辑器，填写预计交付、验收标准、最终文件/链接。批量入口在同一弹窗切换任务，隔离各自草稿并逐项保存。
- 交付编辑器写回真实任务 `index.md`，不创建另一份业务数据库，不自动认可文件内容。最终版本验收仍使用已有的明确确认与版本回执。
- 目标面包屑旁新增“目标文件”，自动打开目标 `index.md`，展示目标目录和任务子目录。总览只读，保留底下任务页上下文。
- 任务详情会预取第一层目录；重新进入文件 Tab 先展示缓存，再更新。刷新失败保留原文件列表并提示；每次显式展开子目录会重新验证。只读取请求涉及的目录，不扫描整棵目录或引入定时查询。

“根据任务目标起草”采用已有目标文字作为可编辑草稿，不声称进行了模型推理。需要进一步讨论时打开任务对话，不自动发送指令。

## 可移植的交付记录

`index.md` 中的 `<!-- paws:delivery:start -->` / `<!-- paws:delivery:end -->` 可读 Markdown 块是交付约定的权威来源，包含 `Expected deliverables`、`Acceptance criteria`、`Final outputs`。调整交付时应修改这个块；块外原有目标、状态、历史记录和参考链接保留。

保存前使用完整原文件 SHA-256 做冲突校验；共享写入器拒绝超过解析器 256 KiB 上限的完整索引。最终文件仅限当前任务，实际路径离开任务目录的符号链接不可作为可用最终产物；目标总览的目录/文件接口同样核对真实范围。不会因为任务 done、写入交付约定或文件存在而生成验收回执。

编辑器回填已有交付时归一化 Windows/POSIX 路径分隔符，避免 Windows 执行机的已有最终文件在修改约定时被遗漏；此转换只用于显示与名称匹配，不替代机器端权限校验。四项根目录/边界用例保护该行为。

目标总览新增机器端只读 RPC `goalFeatureListDirectory` / `goalFeatureReadFile`。部署前端后还需更新执行机 CLI 才能使用这些接口及交付块解析；正式发布还需独立核验执行机激活回执；本地验证不代表已经上线。

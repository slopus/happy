# 聊天视频保存入口

## 问题与结果

移动端聊天中的 `file(kind=video)` 原来只渲染播放器，没有独立保存动作。原生端先下载整个视频再创建 WebView；下载未完成时只能看到黑框与加载动画，无法从播放器导出。

在原播放器下增加文件名、大小和一直可见的“保存视频”。保存不依赖播放器成功渲染；原生端优先复用播放下载的原始文件并单独持有文件租约。Android/iOS 优先使用已内置的 `expo-media-library` 保存到相册；系统不支持或未授予保存能力时使用已内置的 `expo-sharing` 导出。浏览器下载保留原始视频文件名及认证头。

没有修改原生依赖、权限、配置、安装包标识或 runtime；按当前机器可读契约通过 JS OTA 交付。

原生实测发现 WebView 默认外层 `flex: 1` 在视频下增加元数据后会塌缩。播放器现在将相同尺寸传给 `containerStyle`，并用 `flex: 0` 保持视频比例或音频固定高度；避免只有内层尺寸、外层高度为零。

## 界面约束

- 场景：移动端窄屏会话视频；共享卡片也服务 Web。操作放在播放器外，触屏无需长按或 hover。
- 复用：延续原文件名样式、视频宽度、圆角和 Ionicons。文件名承担收缩空间，按钮至少 48dp 高，不覆盖播放控件。
- 主题：普通与按下表面使用 `surface` / `surfacePressed`，文字及错误使用 `text` / `textSecondary` / `textDestructive`。
- 状态：保存中禁用重复提交；只有相册 API 成功才提示“已保存到相册”。系统分享关闭/取消不冒充保存成功；浏览器只提示开始下载。失败保留重试按钮。
- 生命周期：播放与保存分别拥有缓存文件租约，播放器卸载不会提前删除保存仍在使用的文件；离开卡片或附件上下文失效后到达的下载结果只释放、不启动保存。

## 验证边界

Android API36 模拟器以已有 development 客户端加载真实 `FileView` 和原生保存实现。实际点按后提示“已保存到相册”，MediaStore 出现正确命名、30513 字节的 MP4。独立读回相册文件，SHA-256 与 1 秒 H264 原样本一致，ffprobe 通过；没有申请读取照片/视频权限。播放器区域实测保持 16:9，按钮在其下方独立可触达；320dp 窄屏及切到非默认深色主题后保存入口仍存在。未采集截图，不把语义/几何检查描述为主题颜色视觉验收。

测试没有连接真实账号或发送会话消息；临时入口精确恢复，本轮两个相册样本、Metro/媒体服务、ADB 映射及启动的模拟器均已清理，保留其他视频和 App 数据。

模拟器通过不代表用户手机已更新。用户当前手机上的更新加载、相册文件和原视频播放仍须从同一聊天入口确认；iOS 与较旧 Android 的系统分享未做本轮设备验收。截图和 E2E 录像未被请求，本轮未采集。

发布回执、CI、精确版本与待验状态由 Release OPS 本机 `paws-mobile-video-download-20261125` 记录维护，避免复制可变上线状态。

## 用户反馈：保存按钮持续转圈

首轮发布后，用户实际反馈保存按钮长时间转圈且没有结果。首轮仅验证微小公网样本，未覆盖真实鉴权附件和长时间传输；不能据此认定用户原视频可以保存。原视频的文件名、会话及播放是否成功仍待用户补充，当前尚未确认该实例的根因。

源码确认的缺口及本次处理：

- 原生播放会先下载完整视频，保存再次下载。现在复用就绪或在途下载，播放、保存及仍未结束的系统调用各自持有租约。
- 原先下载与写相册都只有相同转圈。现在区分准备、下载、写入相册和分享阶段，下载显示字节与可用时的百分比；准备和下载阶段可取消保存，复用的后台播放下载不因取消保存而中断。
- 附件描述接口的网络请求及 JSON 读取最多等待 20 秒；原生和 Web 视频传输在 45 秒没有新增字节后中止，不以零字节进度刷新期限。单次超时不自动重试，用户可明确重试。
- 写相册最多等待 45 秒，未完成时尝试系统分享；即使界面已结束等待，也保留原生调用真正结束前所需的文件。系统分享选择不设人为期限，也不冒充相册保存成功。
- 取消兼容当前 RN 的 AbortSignal；重试重置旧进度，切换附件身份后不复用上一视频。

83 项定向测试通过，覆盖原生与 Web 解析、原生 IO 延迟取消清理、文件租约、在途复用与进度、取消后不保存、描述接口挂起/重试/旧响应、写相册超时回退、浏览器超时、既有播放器/附件持久层及 runtime 契约。完整 App typecheck 通过。

API36、已有 `build.paws.dev` 开发客户端以临时入口加载真实卡片和保存实现：通过现有 API 鉴权取得当前测试会话内受控 MP4 的 OSS 描述，再由原生下载、点按保存。MediaStore 新文件为 30513 字节、1 秒 H264；独立读回的 SHA-256 与源文件一致。该 30KB 样本只验证鉴权与保存链路，不覆盖用户原视频或大文件。

人为让响应只发送 8192 字节后停住，真实卡片显示 `6% · 8KB / 119KB`，缩短为 8 秒的验收期限后提示超时并恢复按钮；同一失败附件可重试。在 320dp 原生宽度下，下载按钮与 48dp 取消动作均可触达；实际取消后恢复保存入口，没有误报成功。生产期限仍为 45 秒。仅原生下载 helper 的另一次 1.5 秒故障注入也产生预期超时。

临时入口、生成的 Expo 类型/增量缓存、端口服务、ADB 映射、窗口尺寸与本轮唯一相册对象均已精确恢复或清理，保留其他 App 数据；测试模拟器已退出。没有收集截图或录像，也没有复制认证令牌或签名链接到文件。

整体设备验收保持未完成：原用户手机的原视频下载仍待复验；没有本轮 iOS、旧 Android 或大文件真实设备证据。发布与制品状态仍由上述 Release OPS 记录维护。

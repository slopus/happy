# 新建会话模型目录与连接隔离

## 问题与修复范围

同一机器可以同时拥有原生 Codex/Magpie 会话和绑定 ChatGPT 账号的会话。新建页原先只按机器与 agent 选择最近活跃会话的模型目录。最近会话属于 Magpie 时，ChatGPT 新会话也会展示 DeepSeek 等外部模型，首条消息随后被执行端账号校验拒绝。

现在目录按机器、agent 与明确账号 profile 隔离；`null` 表示原生连接，`undefined` 表示绑定状态未知。未知或没有匹配目录时，只使用连接自身的默认模型，不发送硬编码 GPT 或旧草稿中的外部模型。已有账号目录不再添加目录之外的建议。

设备环境中修改绑定会通知同一登录与服务范围内的其他已挂载控制器，触发一次元数据读取。最终启动还会比较提交快照记录的预期连接和即时授权的真实 profile；不一致时在 RPC 前返回 `binding-version-conflict`。预期连接随首条提交持久化，授权 grant 仍只存在内存。没有新增轮询，也没有修改机器绑定或执行端账号隔离。

## 自动验证

- 原生/账号/另一账号交错目录、未知绑定、缺少目录：真实选择函数回归。
- 新建页模型列表、发送选择、账号变化以及 loading/error：组件回归。
- 两个真实账号 hook 实例在环境绑定修改后同步，推进时间不会增加请求。
- 原生与账号错配、解绑、正确匹配：真实授权客户端到启动 RPC 边界回归。
- 提交 owner/runtime/ops 全链路保留预期连接及草稿，错配前阻止派发。
- 明确默认模型不被已保存的旧模型替代。

修复前观察到相关目录用例 4 项失败，组件误选用例 1 项失败；补充竞态用例 6 项在修复前失败。修复后 App 全量 541 个文件、4,806 项测试通过，App TypeScript 检查通过。Android runtime 契约包含在全量测试中。

另用两个真实现有会话的解密元数据只读重放：即使原生目录更新，绑定账号仍选取自己的 8 项目录；原生连接保留自己的 62 项目录。该检查没有启动模型推理或重放用户业务消息。

## 交付边界

这是共享 JS 修复，适用 Web 与 Android；无原生模块、图标、权限或 runtime 修改。发布仍走项目既有 PR preview 与 main Web/production OTA 流程。本报告不代表正式上线、浏览器交互或手机加载已验收。

既有失败会话与旧执行器不被自动更换连接、切模型或重放任务。需要 DeepSeek 的用户仍须使用实际连接到 Magpie 的会话；ChatGPT 账号连接自身不承载该模型。

# 会话目录快照保留与取消释放

## 问题

MacBook Air正式项目页的完整历史在约20.8秒、14%时返回快照不可用，远未达到五分钟有效期。相同执行端在此窗口没有重启；目录缓存的两槽FIFO会因第三次创建逐出未过期快照，回归已复现相同失败。多个首次读取还会共享同一token，直接释放该token会误伤另一个读取者。

## 修改

- 未过期快照不为新创建逐出。按实际驻留字节及每个pending reader最坏64MiB预留，维持128MiB总预算，并限制32个token；容量不足只拒绝新的创建。
- 同项目只共享底层原始目录读取；每个reader独立预留、冻结快照和随机token。释放一个reader不影响另一reader。
- 新增经过项目授权、canonical path和运行期关闭检查的释放RPC。未知、重复、过期和跨项目token返回false，不释放其他对象。
- Web取消/校验失败时尽力释放未完成快照；首包迟到也会释放，完成缓存保留供分页。释放请求在账号、加密实例及跨页签runtime撤销时受围栏保护，旧CLI不支持不替换原错误。
- 五分钟固定TTL、完整指纹、页大小、Task权威分组、显式历史、180秒截止及原有新建/切换能力保留。无新轮询、服务、数据库或原生修改。

## 紧凑索引集成后的租约补验

- 缓存、目录遍历和每个分组调用分别持有租约；refresh、过期与LRU只退役缓存，最后一个活跃调用结束后才释放token。分组调用在`finally`中归还，传输内容仍是纯数据。
- 空闲清理使用单次五秒截止和同机器共享清理栅栏，避免连续fresh读取与旧释放竞争容量。没有状态轮询。
- `pagehide`清空文档缓存并撤销目录遍历；恢复后使用独立读取标识，迟到首包只回收旧token。浏览器卸载仍是尽力清理，固定TTL继续兜底。
- App两文件定向126项及完整类型检查通过，覆盖八次fresh、一快照容量、活跃分组与LRU/refresh、cache-hit独立归还、取消、owner撤销、pagehide及迟到首包。CLI合并后目录/runtime/index/service共120项通过、1项跳过；正式性能验收另记。

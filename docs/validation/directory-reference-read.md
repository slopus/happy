# 目录链接读取修复

## 问题与结果

聊天中的目录链接与文件共用工作区入口。项目外引用调用旧 `readFile` 后返回 `EISDIR`；项目内 `workspaceReadFile` 返回 `Not a regular file`。原 UI 将两种结果都作为文件读取失败显示。

仅在收到这两种非文件响应时，以原读取范围对应的已有目录 RPC 验证目录并取得条目。目录在原文件工作区展示，子目录与文件按完整路径打开；空目录有明确提示。普通文件读取不增加请求，权限失败不回退到更宽范围，不要求重启当前 CLI 会话。

目录不进入编辑、保存、版本历史或文件引用流程。若原文件已变成目录，已有唯一缓存草稿保留、可复制或下载，关闭仍需显式丢弃确认。目录名中的 `.md` 或 `.mp4` 不决定类型。

## 界面依据

PC Web 文件工作区沿用现有 `WorkspaceTreeRow` 的密度、图标、焦点及 hover 表面；文字与表面消费当前主题语义 token。列表目录优先、按名称排序，拒绝路径分隔符、`.`、`..` 及不可浏览类型。当前标签、刷新、关闭入口沿用原流程。

## 验证

- 回归先复现两种目录错误，再修复；目录列表失败仍保留权限错误。
- 文件工作区、目录列表、控制器、历史、Markdown 链接及导航定向回归通过；类型检查通过。
- 独立评审发现并修复“文件变目录后清空缓存草稿”，补充读取期间和加载后的草稿保护、可见导出及关闭确认回归；最终复审无阻塞问题。
- 发布与正式页面验收结果单独记录。自动测试不代表用户浏览器已加载修复，未验证原生手机交互。

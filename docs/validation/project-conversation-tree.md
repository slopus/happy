# 项目会话导航复用文件目录行

用户反馈当前右侧会话导航标题忽左忽中、空目录占据大块高度、默认全展开，且要等待很久。用户明确选择沿用既有文件夹目录样式，默认收起并保留展开记忆。本次直接修订真实组件，未制作另一套静态原型。

## 来源与边界

- Before基线：`da3427b109c08b17a6913a07b5a5a42ccd44b5d0`。在正式入口的对应项目实际核对，右栏338 CSS px，原文件夹按钮`justify-content:center`、行高36px；逐组路径、空态和重复新建入口叠加造成留白。当前正式版已无右栏搜索。
- 原组件：`WorkspaceDirectoryTree`的DirectoryRow。抽出`WorkspaceTreeRow`后，原文件目录与会话目录使用同一行布局、字体、主题及焦点实现。主区、项目框架和右栏宽度保持现有布局。
- 每行统一左对齐，标题单行省略，数量和右侧“＋”保持可达；会话行同样紧凑。删除每组常驻路径和第二个空态新建按钮；完整scope保留在可访问标签。
- 当前主题的`surfacePressed`、`surfaceSelected`、`textLink`覆盖hover、选中及不改变尺寸的Web焦点。新建忙态只在原“＋”位置显示小指示器。

## 展开与读取

- 复用已有`sidebarGroupExpansion`及原子更新器；按机器、项目、scope区分，默认收起。账号/server隔离由现有账户本地存储负责，键不包含短期runtime generation。
- 已知目录直接来自项目定义，增删、改名不等待历史扫描；对应旧行和分页可保留。全部收起时不读取catalog，revision只标记需要更新。
- 用户展开后立即呈现已有缓存和已同步的普通scope会话，包括idle/completed。Task归属仍只接受权威历史，不把旧Task元数据当作授权。
- 展开需要完整历史时才启动既有目录读取；继续复用完成snapshot、分页、取消及180秒单次截止时间。完整历史仍受原协议的全账户密文传输限制，未声称实现按folder快速查询。
- 全部收起时取消旧遍历、清除自动排队读取；显式刷新仍保留。scope变化使旧epoch失效，迟到结果不能恢复旧目录、覆盖新名称或吞掉新的读取。

## 验证

102项定向回归通过：Navigation45、model12、原文件树4、目录协议34、OTA runtime契约7。新增默认折叠/记忆/取消、scope变化/旧响应、自动与显式排队区分、普通已同步历史和键盘焦点回归均先失败后修复通过。App完整类型检查及独立评审另按当前最终提交复核。

正式Before页面及行布局已通过Ego核对，关键状态按当前Happy浏览器进度协议上报；本轮未在PR公开附件中发布用户项目截图。用户对PR前后对照图的异步选择仍待回复，不记为用户已批准。新版合并后的默认收起、展开及刷新记忆须以同一正式项目的Ego结果为准，实际结果及发布回执记录于本任务唯一Release OPS实例；不将自动化回归或Before像素称为After已验证。

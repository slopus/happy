# 项目会话加载恢复与移除搜索

用户截图显示右侧会话区域只有加载动画、未知数量显示为0，并明确不需要搜索。继承PR875的立即显示项目分组、未知数量、新建入口及启动revision合并，本次进一步移除搜索，并保证异常加载可以结束和重试。

## 行为

- 删除搜索输入、query状态及相关分支；保留全部/待处理/执行中筛选和历史分页。筛选没有结果时，有后续页的分组仍可继续加载。
- 整轮catalog读取、本地解密和分组解析共用一次180秒截止时间。既有正式验收记录中的健康首次读取约85秒，因此不采用会提前中止正常读取的60秒总时限；首轮完整目录的网络成本仍然存在。
- 超时立即停止动画，保留已有行和数量，显示现有本地化超时提示及重试按钮；不由定时器自动重试。排队的旧revision在取消时清除。
- 取消会立即结束catalog Promise并逐出对应未完成缓存；已完成目录供分页复用。重试拥有独立RPC读取身份；迟到的RPC、密钥或metadata解密结果不再继续分页、覆写分组或计数。
- 生命周期清理取消读取并清除截止时间；StrictMode重新执行效果不会被旧请求的finally清理掉。保留PR875的并发新建与目录完整ID去重。

## 验证

| Case | 证据 |
| --- | --- |
| 无搜索、筛选与分页仍可达 | Navigation组件回归；翻译覆盖全部10种语言 |
| 首次未知数量、分组与新建入口 | 继承PR875回归及本次未知数量/85秒健康读取回归 |
| catalog或分组读取不返回 | 假时钟推进180秒后结束动画、可手动重试 |
| 两阶段累计时限 | catalog耗时170秒，分组继续10秒后统一超时 |
| 超时旧响应迟到 | 新请求成功后旧响应不能覆盖新列表；RPC读取身份不同 |
| 解密期间取消 | key、preparation、metadata各阶段拒绝并禁止后续处理 |
| 刷新失败、卸载和StrictMode | 已有行及总量保留；取消监听及定时器清理；替代读取正常完成 |
| 原范围新建/缓存重聚合/分页/归档等 | 原有Navigation、model及projectGoals回归继续通过 |

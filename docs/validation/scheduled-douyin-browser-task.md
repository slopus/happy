## 权限边界

任务在 00:27:55.201 进入 waiting-for-input，管理页显示 Needs approval，普通会话显示原生批准选项。用户明确允许本次抖音只读浏览器操作后，逐条核对并批准本次命令，没有选择整会话免审批或修改全局 Codex 配置。

首次截图因抖音将同一搜索页的查询参数规范化而拒绝捕获；执行器停止并披露，原空间保留。核对返回信息后，以已确认的精确地址继续原空间、原标签和原 runId，补齐链接并成功上报最终关键帧；未重新搜索或换用其他浏览器。原定时回合的 completed 只表示该回合已结束，补齐过程属于普通追问，不冒充原回合已经完整交付。

普通追问还真实暴露了权限继承缺陷：界面依据执行端的 currentOperatingModeCode 显示 Ask first，但发送元数据忽略该字段，回落新建会话的 yolo 默认。修复 [messageMeta.ts](../../packages/happy-app/sources/sync/messageMeta.ts)，让已有 Codex 会话沿用执行端当前档位；显式的新选择仍优先。

新增四种较窄档位的失败回归及显式选择优先级检查，修复后相关 56 项测试、完整 App typecheck 通过。实际刷新开发页面、清除仅此测试会话的本地覆盖并恢复原生 default 后，真实追问的消息元数据保持 default（非显式覆盖），执行端同样保持 default；最后将测试会话恢复为 Request approval。未做手机原生验收、APK、OTA 或正式部署。

开发环境的 Expo 曾生成空路由类型，首次 typecheck 因此失败；从真实 sources/app 路由按 Metro 的测试文件排除规则重新生成 ignored 类型缓存后通过。未以产品源码放宽类型检查。

# 下线 Web 存储恢复横幅与手动导出流程

2026-11-22；基线 `af77e8e047db0d22bdbfb43c84eedce255b72ab8`。

用户不需要这套恢复提示和手动导出流程。本次移除交互，不为其增加新的展示方式或恢复工具。IndexedDB 自动迁移与保存继续运行。

## 已确认的原因

1. `WebStorageStatus` 位于应用根部的普通布局流；每次异步保存及延迟编辑都会经历 pending/完成。正常写入也让横幅出现或消失，改变整个工作区的高度。
2. 导出只是下载数据库快照，没有对应的导入、恢复或冲突处理入口。导出不改变恢复记录；重载又会读取相同副本，因此两者不能消除恢复提示。
3. 历史迁移差异、损坏旧源与写冲突副本被合并成一个恢复计数，没有当前账号或当前编辑是否确实需要处理的判断。内部保留副本不等于用户需要执行恢复操作。
4. 所有横幅按钮的 Promise 错误被吞掉。保存重试排除真正的 CAS 冲突，因此也不具备自动解决冲突的能力。
5. 原样保存仅在 revision 已落后时才豁免；同 revision 下重复写入仍增加版本号，导致其他页面误判为有更新。已用两个合成数据库实例复现。

## 修改与保留

- 删除根布局中的横幅、Web/原生占位组件、手动导出函数及对应文案。
- 删除仅用于横幅的状态订阅、广播和 focus 全库检查；它们原先只置位提示，从未协调业务状态。
- 原样内容和已有语义等价快照不再增加 revision；撤销校验始终先执行，首次删除仍保存 tombstone。
- 保留事务提交、发送前 flush、未保存编辑缓冲、页面退出保护、CAS、账号/记录撤销及原有数据副本。未自动合并冲突、重放队列或清理用户数据。
- Developer 的按需计数诊断及安全缓存清理仍在；数据库确实无法打开时的启动重试仍在。

## 验收中修复的问题

1. 页面先挂载、账号后初始化时漏刷新；桌面列表 `flex: 0` 使宽度塌缩。已修复并复验真实页面。
2. 一次性时间已过时错误显示完成、恢复按钮必定失败。现在以真实历史显示终态；过期 pending 可取消，重新设定未来时间后可恢复。
3. 另一个 daemon 的恢复观察误把仍在启动的任务标成 uncertain。恢复领取只观察，首次原子领取才取得投递许可。
4. 重复立即运行请求重新广播重要通知、跨任务同请求 ID 造成 journal 冲突。请求别名单独持久化，run 使用独立 UUID；幂等返回不广播。
5. 回执倒序及输入合并可能错记完成。保存序号高水位，锁定第一次准确根回合，定时消息独占队列项；本地命令和未派发失败释放自己的输入占用。
6. 数据库短暂失败后截止工作丢失。保留失败项，仅在机器重连或用户刷新事件单次重试，无周期业务查询。
7. macOS `/tmp` 与 `/private/tmp` 的路径别名误拒固定会话；使用 realpath 比较。relay 在线标记可能暂时滞后于 worker 退出，复用前另查实际进程；未知状态拒绝启动，不终止已有 worker。

初次使用完整全局 Codex 环境的两条任务到点后进入 running，但模型没有在验收时限内返回；原生日志随后记录超时。独立的无用户配置请求及临时 Codex home 中的真实请求成功，尚未定位全局配置中的具体影响项。未关闭用户全局 hook、MCP 或修改默认模型，也不将超时记录改写为成功。

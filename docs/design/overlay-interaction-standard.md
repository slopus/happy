# 浮层与外部点击关闭设计规范

适用范围：Paws 自有 PC Web 的菜单、下拉选择、自动补全、Popover、Dialog 和 Sheet。新建、修改和评审这些界面时均遵循本规范；原生移动端需按触控、返回键和安全区单独设计，不直接复制 Web 的事件处理。Tauri 不在支持范围内。

核心要求：**临时浮层容易退出，内部操作不误关，关闭不丢内容、不抢焦点、不穿透触发其他动作。**

本文定义产品行为与验收要求。它不是现有全部页面已通过验收的声明；历史实现按实际受影响范围逐步收敛，缺口必须记录。

## 1. 先选择表面类型，再决定关闭方式

| 类型 | 例子 | 点击外部 | Escape / 明确关闭 | 对背景的影响 |
| --- | --- | --- | --- | --- |
| 临时非模态菜单/选择器 | 更多菜单、模型/账号/目录选择、输入建议 | 默认关闭当前浮层 | Escape 关闭；再次点原触发器收起 | 背景可交互；不吞掉外部控件自身的正常动作 |
| 无未保存内容的模态查看窗 | 文件预览、使用量、浏览步骤 | 点击背景遮罩关闭 | Escape 或关闭按钮关闭 | 遮罩拦截点击；只关闭窗口，不执行遮罩下的按钮 |
| 有未保存内容的编辑窗 | 表单、交付编辑器 | 不直接丢弃并关闭 | 明确取消/关闭与 Escape 走同一份草稿保护逻辑 | 保留草稿，或明确询问保存/放弃；不得用默认外点关闭代替决策 |
| 确认/授权/危险操作弹窗 | 删除确认、权限确认、提交中的关键操作 | 默认不关闭，也不代表确认 | 有明确取消时，Escape 等价取消；不可取消阶段保留并说明 | 只由明确动作提交；关闭绝不等价于同意 |
| Tooltip | 截断说明、快捷键提示 | 不独占背景点击 | 失去 hover/focus 后消失；支持键盘等价获取 | 不承载必须操作，不能成为关键说明的唯一入口 |
| 常驻面板与折叠内容 | 文件栏、右侧工作区、详情展开区 | 保持当前状态 | 使用明确的收起/返回入口 | 不套用临时菜单的关闭规则 |

菜单里包含搜索框，不等于它是需要保留草稿的编辑窗；选择器的临时筛选文字可随关闭清理，用户正文、文件草稿和已选择值不可顺带清空。类型或例外必须由具体产品语义决定，不能由组件名、颜色或是否使用 Modal 推断。

## 2. 打开、内部操作与外部关闭

1. 同一职责的选择器同时只打开一个。切换电脑、目录、模型等入口时，旧选择区收起，新选择区打开；选中值只在明确选择时变化。
2. 原触发器属于浮层所有者。再次点击应关闭，不得出现 pointerdown 先关、click 又重新打开的循环。
3. 浮层内部的搜索、滚动、文字选择、选项、滑轨和拖动必须正常工作。不能因选项的子元素、图标或 Portal 不在触发器 DOM 子树内，就把它判为外部。
4. 外部包括聊天区、左右侧栏、表单其他字段、其他输入框和面板周围的透明空白。只有局部栏内可关闭，不满足整页外点关闭要求。
5. 点击外部只改变本浮层的展开状态，不自动保存、发送、切换账号/模型、提交表单或删除数据。
6. 非模态浮层收起后，外部控件继续完成同一次正常点击。例如点击另一个输入框，菜单收起且该输入框获得焦点。模态遮罩则消费该次点击，不把动作传给下面的页面。
7. 关闭后重开必须立即可用。监听器、悬停状态、拖动状态及未完成的 Escape 手势不得遗留到下一次打开。

## 3. 嵌套与所有权

- 每个浮层必须知道自己的面板、触发器、所属工作区/输入框和必要的子浮层。Portal 的节点也须明确纳入边界。
- 使用真实 ref 或明确所有者标识判断内部区域，不以“任意 message-composer”“任意菜单”这样的全局选择器排除其他实例。
- 子菜单打开时，子菜单内部操作不能误关父层。点击父层其他部位应退出子菜单并保留父层，再按该部位的语义完成动作。
- Escape 每次只交给最上层可取消表面；关闭子确认后，同一次 keydown/keyup 不得继续关闭父层或触发背景快捷键。层级协调由宿主负责，不能给每层各绑一个不协调的全局 Escape。
- 打开确认框等新模态流程前，关闭产生它的临时动作菜单。确认框的外部点击政策独立生效。
- 切换路由、会话、账号或数据所有者时，清理旧所有者的临时浮层；迟到的测量或异步结果不得把它重新打开。

## 4. 焦点与键盘

| 关闭原因 | 焦点要求 |
| --- | --- |
| Escape / 明确取消或关闭按钮 | 在原触发器仍存在且可用时返回触发器；已离开该页面时不恢复到旧节点 |
| 点击另一个输入框或控件 | 保留外部点击形成的新焦点，不延迟抢回原触发器 |
| 选项选择完成 | 普通选择器按任务返回触发器；输入建议按需回到正文输入；导航动作交给目标页面 |
| 模态背景点击 | 关闭后回到触发器或原任务的合理位置；该次点击不能激活背景目标 |

- 模态窗口打开后把焦点移入，Tab/Shift+Tab 限定在当前窗口内；非模态输入建议应保留输入焦点，不为展示列表强制切走。
- 触发器提供可读名称及正确的 expanded/haspopup 状态；面板按真实用途使用 menu、listbox/radiogroup 或 dialog 语义。不要把同一窗口重复声明成多个模态所有者。
- Escape 不修改用户正文、光标或已选择值来“假装关闭”。输入法组合期间不得误选、误提交或用 Escape 关闭外层而打断正在处理的输入。
- 自动补全的关闭状态只对应当前文字和光标状态。用户继续输入、移动光标后应允许重新建议；退格回曾关闭过的文字，也不能永久隐藏。

## 5. Web 实现约束

### 非模态外点监听

优先复用 [`useWebPopoverDismiss`](../../packages/happy-app/sources/hooks/useWebPopoverDismiss.ts)，通过 `enabled`、`isInside` 和 `onDismiss` 声明边界。Web 使用捕获阶段的主指针 pointerdown，避免子元素 stopPropagation 导致漏关，同时覆盖鼠标、触控笔和触摸的指针路径。右键菜单手势按自己的协议处理，不把所有指针按钮一律当作普通点击。

- `isInside` 至少包含真实面板和原触发器；有 Portal、多个触发器或嵌套内容时显式补齐。
- 监听仅在浮层打开时启用，关闭/卸载后移除；回调读取最新所有者与状态。不得建立定时轮询来反复查询浮层、焦点或几何状态。
- 外点关闭不要调用 preventDefault 或把焦点强制拉回，除非该表面明确是阻断背景操作的模态。
- 组件的原生入口不能无条件读 document/window/HTMLElement；Web 专用行为优先用 `.web.*` 实现或明确平台保护。

**该 Hook 只提供外部主指针检测。它没有自动实现 Escape、焦点管理、嵌套栈、焦点陷阱或 iframe 桥接，宿主仍须分别实现并验证。**

### 模态背景与透明容器

- 遮罩必须覆盖该模态阻断的完整视口，与实际对话内容平级。优先复用已有 Modal 宿主；不要在每个内容组件里再叠一套关闭处理。
- 只有背景颜色，没有点击处理，不算关闭遮罩。只覆盖局部侧栏的 absolute View，也不能保证跨栏关闭。
- 对不应挡住点击的全宽透明布局容器，使用 Web 的 pointerEvents="box-none" 或等价布局；保持可操作内容正常命中。不要靠不断提高 zIndex 修复边界问题。
- 对直接使用 RN Modal 的只读文件查看窗，可参考 [`WebModalBackdrop`](../../packages/happy-app/sources/components/WebModalBackdrop.web.tsx)。它是点击背景，不是监听整个父容器；内容点击不能冒泡到背景关闭目标。
- 复用 BaseModal 的表面需显式选择 closeOnBackdrop；确认和编辑语义不得被默认值覆盖。

### iframe、拖动及视口

- iframe 内的指针事件不会冒泡到父 document；嵌入网页不能仅凭父页面 capture listener 就声称支持外点关闭。按表面类型使用覆盖 iframe 的模态遮罩，或明确的事件/焦点桥接，并做真实浏览器验收；未实现的入口记录缺口。
- 拖动从面板内部开始后移到外部，不应在指针释放时突然被当作另一轮外点关闭；取消、失去捕获及卸载要清理拖动状态。
- 窗口缩放、滚动、缩小及锚点消失后，浮层仍须可达或按产品语义关闭。用 ResizeObserver、滚动/尺寸事件驱动定位，不用轮询。

## 6. 新增表面时的设计说明

在需求、PR 或组件说明中简短填明以下内容即可，不必另建复杂配置系统：

```text
入口与用途：
类型：非模态菜单 / 只读模态 / 编辑 / 确认 / Tooltip / 常驻
所有者与内部边界：面板、触发器、Portal、嵌套层
关闭方式：外点、重复触发、Escape、明确按钮
内容保护：哪些值/草稿保留，哪些动作才能提交
焦点：键盘关闭回哪里，外点如何保留新焦点
特殊边界：跨栏、iframe、拖动、路由/账号切换
```

有意不支持外点或 Escape 时，写出内容保护/业务原因和可见的退出入口；“还没加监听”不属于设计例外。界面颜色与交互态继续遵循根 CLAUDE.md 的语义主题 token 约定，本规范不另设一套视觉数值。

## 7. 最小验收清单

| Case | 必须观察到的结果 |
| --- | --- |
| 打开 → 点击同一触发器 | 一次点击收起，不重开 |
| 点击内部文字、图标、搜索框或选项 | 不误关，选项自身动作能完成 |
| 菜单内滚动、选择文字或拖动滑轨 | 不丢内容、不误触外点关闭 |
| 点击本栏、其他栏与透明边距 | 按类型关闭；无局部“死区” |
| 外部控件停止事件冒泡 | 非模态菜单仍可关闭，外部动作正常 |
| 点击另一个输入框 / 另一个实例 | 旧菜单收起，新目标正常交互且焦点不被抢回 |
| Escape、关闭后重开再 Escape | 每次只处理正确层级，无残留手势 |
| 子菜单或子确认关闭 | 父层保留；无事件穿透到父层/背景快捷键 |
| `/co` 关闭 → `/com` → 退格回 `/co` | 建议能够重开，正文未被改写；`@` 同理 |
| 编辑内容未保存 / 正在提交 | 不因背景点击静默丢失或重复提交 |
| 关闭后切路由、会话或账号 | 旧监听、焦点恢复及异步回调不影响新所有者 |
| 存在 Portal、iframe 或视口边界 | 分别验证；不能拿普通 DOM 通过替代 |

验证采用风险相称的组件/DOM回归和真实浏览器操作。每个断言验证用户可观察行为，不以“存在 onClose prop”替代点击后的结果。源码检查、隔离组件、生产页面与用户设备分别报告，不互相冒充。

是否采集前后截图与视频遵循仓库当前约定；截图选择未回复不能被写成已确认，也不自动成为修复门禁。没有图片不能据此省略必要的行为测试。

# 入口与工程／会话关系修订讨论

2026-11-26。用户指出会话标题栏空间有限，并强调并非所有会话都制作视频。本记录是源码核对与修订建议；旧原型已经验证的点击流程不代表入口位置获得认可。本轮未修改产品代码或发布新稿。

## 当前开发分支的事实

- `MotionProjectsButton` 只按 PC Web、可写工作区、会话与连接状态显示，没有检查该会话是否引用影片。它被插入普通会话及项目会话的标题栏，因此范围过大。
- `catalog.ts` 按 server 与 canonical 工作目录建立索引，存工程路径和最近打开时间。目录相同的两个会话共享发现结果；这只能说明工程可被发现，不能说明本次会话正在制作这条影片。
- 原生工程在执行机保存，打开、编辑和 AI 回改通过已有会话 RPC。编辑器绑定、当前打开请求和文档版本校验已经存在，但不是持久的会话—产物关系。
- 当前文本 `ArtifactSchema` 仅有 html/markdown。通用产物是拟议的产品收纳层，不能直接把影片文档塞进现有文本版本接口，或宣称多类型产物中心已经实现。

## 硬约束与原有假设

硬约束：标题栏空间有限；普通编程、研究和聊天不能被强加视频工具；工程应跨会话持续存在；保留原生文档、目录授权、草稿与目标版本校验。

需撤回的假设：「工程可从当前目录发现」等同于「工程与当前会话有关」；「所有会话都需要一个剪辑入口」。入口应由工作内容和显式引用决定。

## 建议的入口

| 位置 | 出现条件 | 任务 |
| --- | --- | --- |
| 对话中的具名工程卡片 | 本会话创建、导入或用户明确关联了影片 | 首次打开、再次打开、继续修改 |
| 右侧能力中心的产物区域 | 有本会话相关产物时 | 汇总可编辑工程和导出文件；按类型区分 |
| 项目页的产物列表 | 进入 Paws 项目或工作区 | 跨会话查找同项目下的影片、网页和文档 |
| 输入框已有添加内容菜单 | 用户主动引用已有工程 | 关联时选择工程，不占用标题栏常驻空间 |

优先组合为工程卡片首开、右侧产物区域回访；项目级列表承担长期查找。会话未引用影片时不展示视频专用入口。选择影片参与 AI 修改后，复用输入区的引用条，显示当前作用的具名工程，并允许移除。

## 建议的对象关系

- Paws 项目／工作区是组织与访问范围，包含会话和多种产物。普通会话可以没有产物；不强制把所有普通会话转换成视频任务或 Goal First 项目。
- 影片工程是可持久编辑的产物，Paws 保存稳定身份、名称、类型、执行机和位置引用；原生编辑器继续保存时间线、素材、文档和历史。关闭或删除会话不会隐式删除工程。
- 会话通过显式引用关系连接零个或多个产物。同一影片可在创意、声音、剪辑等不同会话继续；创建会话只作为来源记录，不是唯一拥有者。
- 一个会话讨论多个工程时，每次 AI 修改请求都明确携带目标工程引用与原生版本；切换界面上当前工程不改变已排队请求的目标。没有明确目标时不能按目录猜测。
- 工程创建／导入成功后可登记来源会话；扫描发现只能作为可关联候选，不自动建立会话关系。从工程发起「继续修改」时，选择或新建相关会话，并带入工程引用。
- 打开编辑器与启动 AI 会话分别处理：点击工程只准备编辑器；明确交给 AI 才提交修改。执行机服务继续按工程打开动作启动或复用。当前实现仍依赖 session RPC，独立项目入口需要相应适配，尚未实现。
- 首版保持已有目录和账号／执行机边界。跨工作区工程应进入其所属工作区继续，不能通过一条关联记录扩大旧会话的目录权限。

建议数据只包含薄层元信息：`ArtifactRef`、原生工程位置、`SessionArtifactLink`（创建来源／显式引用）与当前输入上下文；不是另存一份影片文档。可先聚合现有文本产物和影片登记数据，不强行统一各编辑器的版本存储。

## 尚待验证

目前只形成源码事实、入口比较和关系模型；没有新的浏览器、真实后端或用户认可证据。下一稿应并列展示普通会话无剪辑入口、关联影片的会话卡片／侧栏、跨会话打开同一工程三种情况，再检验发现性与上下文是否明确。当前固定标题栏原型保留作历史对照，不作为已接受的正式设计。

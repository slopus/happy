# 应用服务短链路

Codex 应用会话保留服务授权及原生 Agent loop。浏览器仍只持有应用连接；执行端使用指定账号，平台凭据不发送到浏览器。

## 发送流程

创建会话时校验并固定模型、推理强度、工具权限和账号。发送时重新校验授权、身份和执行机在线状态，接收幂等任务，再通过原生 SDK 的 send/watch 执行。Codex 每条消息不再单独启动 model/list 探测进程。模型不可用仍由原生执行器明确拒绝，不切换账号或模型。

Codex 设置和创建绑定可以复用同一账号身份下不超过 60 秒的可信目录。每次读取仍检查当前授权和在线状态。相同授权的并发目录读取共享一次探测；过期结果重新查询。缓存不保存或延长授权。Claude 的设备本地身份仍通过实时探测验证，不复用已完成目录。

新建与恢复应用会话使用仅包含指定登录凭据的独立 Codex home。应用提示词及原生工具由既有绑定策略提供，避免继承宿主 MCP、全局指令、插件及配置。普通 Paws 会话维持原配置继承行为。应用会话已有固定模型，不再为了可编辑模型选择器阻塞启动。

## 验证

| Case | 通过标准 | 验证 |
| --- | --- | --- |
| C1 发送 | 无重复目录探测，撤销/停用/换账号仍拒绝 | 授权及真实 HTTP 路由测试、独立评审通过 |
| C2 设置读取 | 同授权合并探测，Codex 目录短期复用且不缓存授权 | 真实测试数据库回归、独立评审通过；Claude 换身份仍实时探测 |
| C3 原生启动 | 应用绑定配置隔离，普通会话不变 | CLI 账号/原生执行回归、独立评审通过 |

- CLI：89 项针对性测试通过，包括账号凭据隔离、普通启动、恢复、原生消息、取消、重复请求及应用策略；构建包含类型检查。
- Server：授权、绑定、原生任务、快照历史、目录合并及真实 HTTP 路由回归通过。另有 6 项打包 SDK 消费端测试通过，覆盖两个应用、越权拒绝、断线恢复、取消和配额失败。
- 原生模型速度及正式浏览器验收须另行记录；单测与模拟执行不能证明实际首字耗时。

## 已确认的旧链路样本

一次只回复一个字的请求：接收至结束约 42.9 秒。其中原生进程约 1.4 秒启动，model/list 约 5.0 秒，thread/start 约 5.1 秒，turn/start 至正文约 19.6 秒，正文至原生结束约 9.6 秒。日志同时出现宿主 MCP 初始化。该样本不能证明所有等待的根因，也不能用于承诺改造后的固定速度。

无需数据库迁移。Server 与 CLI 应分别部署；原有活跃 worker 不自动升级。不会主动停止其他会话或重写旧线程。

# Goal First / Happy 任务复盘整理

依据本会话已确认的规则实施，不重新打开目标选择。根仓库保持干净 main，工程在 sibling worktree。

1. Shared wire：在原任务 index 的 paws:review JSON 块保存整理摘要、证据、待判断项、真实缺口、按产物版本绑定的历史认可和状态修改事件。status 仍只在 YAML 维护。提供校验、状态修改、撤回函数，拒绝损坏块、重复状态及失效撤回；256KiB 文件上限。
2. CLI parser / prompts：解析复盘记录供 Happy 展示；历史认可按真实产物 revision 匹配，变化即失效。任务执行提示和会话基础提示接入平时自动维护；不增加轮询或后台模型任务。
3. Happy 原位 UI：沿用 TaskCards、主题、编辑模态和加密文件 RPC。卡片状态可点击修改，与交付认可分开。复盘弹窗支持项目/选中任务，先显示待判断事项与缺口，自动整理与依据可展开，状态修改可撤回；用已有 author 会话启动 AI 复盘。批量范围只以用户所选任务为准，不因搜索/过滤隐式扩大。
4. Goal First Skill / OPS：复用归档整理入口，新增复盘协议与可执行记录工具，日常记录和集中复盘使用同一格式。已有明确认可沿用；其他疑点集中处理，仅阻碍推进才问；复盘不补做业务工作。Skill 源维护在内置盘真实仓库，保留既有用户改动。
5. 验证：wire codec 状态/撤回/损坏输入回归，真实档案 parser 与历史认可变更回归，UI 手动状态/待判断优先/选择范围/错误与撤回行为测试，相关 suite/typecheck/build。源码、真实浏览器、本机运行时、正式发布分别报告。

界面：保留截图中的卡片与全局对话布局；复用语义 surface/text/divider 与 GoalBoardButton。弹窗明确关闭/返回，编辑不外点丢稿；离线/只读禁用修改，异步回调按账号和 scope 隔离。截图尚未要求，不启动截图采集。

## 正式工具回合发现的兼容缺陷与补修

旧版客户端的 MetadataSchema 会裁掉未知顶层和 capabilities 字段；活动时间写入器再把整份裁剪结果回写，令 acpPermissionMode / acpPermissionPolicy 消失。执行端仍在完全访问，页面却无法撤回。已用新旧真实 schema 复现该机制；运行日志没有写入端身份，不归因具体设备。

补修仅涉及 CLI：统一接收较新 metadata 的 socket / CAS conflict / success ACK 三条路径，发布事件并保持版本单调；agy 按事件恢复属于当前 worker 的权限策略，健康状态不循环写回。首次绑定与重连各做一次 CAS，保留其他设备的标题和活动时间。执行端退出、归档、替换 PID、session swap 和空元数据都有保护。队列中回调读取最新策略，旧快照不能复活已撤回的完全访问；首轮完全访问要求现有协议的显式选择标志或 live RPC。

回归先确认缺事件/恢复失败，再确认迟到 ACK 回退和 conflict-first 漏通知均失败。补修全量 205 文件 / 2,050 passed + 2 skipped；随后新增的首轮未确认权限回显防护由最终定向覆盖。首轮默认高并发有两项无关子进程夹具 ENOENT，两个 worker 复跑全量通过，没有修改夹具或跳过用例。最终定向、独立窄审、当前 head CI、补修执行端激活和同一正式入口撤回验证分别留证。

# DreamSkin PC Web implementation validation

The opt-in “休闲室内居家” skin is implemented for authenticated PC Web at widths of at least 800px. Appearance keeps the saved Paws palette and light/dark preference intact; switching the skin off restores them. Public share pages keep their own appearance. The original DreamSkin wallpaper is excluded from distribution; the checked-in background is independently generated, with details in `2026-09-27-dreamskin-asset-provenance.md`.

The implementation follows the existing home, conversation, sidebar, modal, tool-group, and composer flows. It adds one desktop workspace photo below the navigator, transparent navigation/home/session layers, an actual-main-width reading surface, compact turn identities, and direct share/pin actions where the header has room. Search, settings, tools, logs, code, modal panels, and the right panel retain opaque reading surfaces. System reduced-transparency and increased-contrast preferences select solid materials.

Validation: focused home, session hydration/agent-space, transcript pagination/browser-progress, sidebar, settings/skin, theme, and public-share tests; TypeScript typecheck; deterministic ZIP/token inspection; and Web export. The exported photo checksum must match the source asset. Independent source review found no remaining definite code defect after fixes to the React Navigation outer background, modal backdrop, avatar width, pin/Focus behavior, and share width restoration.

The local exported app loaded in Ego browser but stopped at the login page. No authenticated home/conversation screenshot or interaction verdict is available yet. Before PR or release, verify the final build in an authenticated browser at wide and constrained widths, especially the expanded “4 commands / 2 tools” case, readable photo layering, `/new`, a settings modal over the conversation, and sidebar/right-panel resizing. Do not treat the source review or a concept image as proof of that visual gate.

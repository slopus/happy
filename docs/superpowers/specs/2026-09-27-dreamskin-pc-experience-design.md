# Paws PC「休闲室内居家」沉浸皮肤设计

**日期：** 2026-09-27
**状态：** 设计已批准；PC Web 实现位于 DreamSkin 功能分支，验收记录见 `2026-09-28-dreamskin-implementation-validation.md`

## 目标

让 Paws PC Web 获得参考图的核心体验：整页照片建立氛围，深色侧栏融入背景，问候语和输入框成为首页的视觉重心；进入会话后，延续同一语言并保持长时间阅读清晰。用户在外观设置中可以切换回原主题。项目、清单、会话、机器、模型和右侧能力面板沿用现有功能与数据。

设计以最终观感为优先。选择「可切换皮肤 + PC 工作区容器及组件的定向改造」，既让效果完整，也让默认外观可恢复。参考图中的 Codex 导航结构和文案不是迁移目标；Paws 自身的信息组织仍应清楚。此前生成的两张概念图只表达色彩和氛围，**不是会话页的布局或信息密度规格**。真实会话的工具执行流、消息列、右栏和输入区以现有产品为准。

## 真实界面核查与可行性结论

2026-09-27 在在线 PC Web 核查了首页、已完成长会话、当前会话、右侧能力面板和文件标签；再与源码逐项对照。用户所示红框的「执行了 7 个命令 / 使用的 Skills」是现有 `ToolGroupView` 的紧凑可展开执行流，不是适合放大成独立大卡片的普通消息。它的密度、展开动作、命令等宽字、输出与权限状态都属于核心交互。

**可实现参考效果，但不能只导入 CSS、替换颜色或将 `ComposeHome` 设为透明。** `SidebarNavigator` 的抽屉、场景和根节点，`SidebarView` 的两级侧栏，`ComposeHome` 的工作区，以及 `SessionView` 的主区和右栏都绘制实色背景；全局 Stack 也默认用 `theme.colors.surface`。需要在 PC 工作区建立统一照片画布，再让指定区域选用相应材质。会话页只在空间允许时露出照片，密集阅读层保持稳定。无需重写会话数据、虚拟列表、项目清单或发送逻辑。

真实布局约束：主导航 60px；左栏可拖拽 250–480px，默认约 360px；右栏可拖拽 280–480px；主区最小 480px；消息宽度上限 800px。右栏在宽桌面持久显示，在 800–1099px 改为抽屉；左栏还有固定、悬停展开、禅模式和用户保存的宽度。**皮肤不能覆盖这些用户状态，也不能用整窗宽度决定会话照片的可见度；必须按扣除当前侧栏后的主区实际宽度响应。**

## 设计决定

### 1. 整体画面

首页照片是一层贯穿 PC 工作区的背景，不作为聊天内容的直接底色。应在桌面工作区容器挂载一次，而不是让每列各自裁切背景；否则侧栏、主区、弹层背后的照片会错位。原图按 `cover` 裁切，初始焦点取包内 `focusX = 0.5`、`focusY = 0.5`，再针对常见视口校正，让人物面部和白猫在首页可见。照片上方有可配置暗色遮罩，首页中下部和侧栏文字区使用更强的局部渐变。静态资源随 Web 版本发布；无图、加载失败、减少透明效果时回退到 `#131313` 和实色表面，避免闪白或文字落在亮图上。

不要把 `#1e1e1e55` 当作所有组件的通用 `surface`。它仅是材质来源色：亮墙背景上的浅色文字会失去对比度。设计分四层：

| 层级 | 用途 | 首版视觉参数，最终以实机对比度校准 |
|---|---|---|
| 画布 | 照片、纯色回退、暗色渐变 | 图片可见，但在文字下方充分压暗 |
| 导航材质 | 主导航、清单侧栏 | 深色半透明，可轻微模糊；文字区域比原始 33% 更厚 |
| 内容材质 | 会话阅读区、代码、工具结果、右侧面板 | 阅读区用横向透明度渐变；代码、工具结果与右侧面板保持高不透明度 |
| 浮层材质 | 输入框、菜单、弹窗、选择器 | 最稳定的深灰表面、细边框和必要阴影 |

这与 Apple 对材质的建议一致：较透明的表面适合保留背景语境，承载密集文字和操作的表面需要更强的可读性。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

### 2. 首页 `/` 与 `/new`

- 左侧继续使用 Paws 的两级导航。主导航保持现有 60px；次级栏保留用户拖拽宽度、固定/悬停展开与禅模式，不为了构图硬改为 300px。侧栏的项目、清单、时间线、归档是同一工作区内的视图切换，不是四张独立页面。
- 当前白色大主区域改为能露出统一照片画布的场景层。首页与 `/new` 复用 `ComposeHome`，但页眉不同；两处均需核查。顶栏和 `VoiceAssistantStatusBar` 活跃时保持足够对比度。
- 问候语与输入区形成同一视觉轴，但使用**两档随可用高度变化的安全布局**：内容放得下时采用照片主体可见、问候和输入区靠下的沉浸布局；短视口或输入区扩展时切换成可滚动内容，并确保输入与恢复动作可达。不可把问候语和输入框按视觉稿坐标绝对定位。Web 首页问候和输入的现有宽度上限是 800px；多行输入最高可增长到 480px，叠加图片生成图库、预设 chips 或失败恢复卡后可能超过一屏。
- 输入框复用真实的机器、目录、Agent、权限、模型、effort/Fast、附件与发送控件；长路径提供截断和查看。现有选择器有遮罩、焦点管理和键盘操作，皮肤仅改表面与状态，不改语义。发送前检查在线机器、有效工作树和图片模式所需风格；不可为了视觉效果隐藏禁用原因。
- 覆盖默认编码/提问、图片插件入口、图片 Agent 风格图库/变体/引用图、深链预设，以及正在创建、恢复草稿、发送失败/重试、离线等状态。右侧能力面板还有摘要/详情、目录浏览、快捷提示和可用性/加载状态，列表应使用不透照片的内容面。图片模式下取消或弱化首页粒子，以免照片与动态点争夺注意力；纯色模式可保留经过适配的粒子。

### 3. 会话 `/session/:id`

会话页保持现有骨架：顶栏，中央虚拟化消息列表，底部输入区，以及按状态出现的右栏、文件和 diff 覆盖层。照片在 `SessionView` 主区的固定底层，**不进入 `ConversationTranscript` 的滚动内容**；同一张照片连续铺满主区，不能为填补左侧留白重复叠图。左侧用较厚渐变压暗但保留环境细节，不能留下整块纯深灰空区。中间是一块连续的深色阅读面，不能每条消息套玻璃卡。消息列仍以 800px 为上限，行高、key、分页、锚点、滚动恢复和「跳到最新」逻辑保持原样。这样工具组展开时不会因为皮肤导致列表跳动。

用户对第一版的阅读面希望**更透明**。宽屏视觉稿以从左至右约 88% → 58% 的深色覆盖作为起点：正文所在左侧更稳，右边界让照片自然透出；单独的代码块、工具组、日志和输入区仍用较厚表面承载文字。阅读面与照片之间的主区遮罩也要渐弱，避免两层暗膜叠加后看起来仍不透明。这些百分比是视觉稿参数，不是固定实现值；必须以真实文本、选区、长执行流和亮部照片校准。右栏打开、主区缩窄或减少透明效果时，阅读面应逐渐加深或退为实色，并保持人物不压正文。

照片可见度以主区实际宽度和右栏状态驱动，初始设计区间如下，实施时用真实视口校准：主区 ≥1180px 时，允许人物位于消息列外侧的留白；主区 800–1179px 时，减弱裁切与对比，只从边缘和顶栏透出；主区 <800px 或右栏/文件/diff 占用空间时，照片退为暗色氛围或不显露人物。以上是**材质强度断点，不是修改消息列宽度的断点**。人物焦点不能逼迫正文偏到一侧；当侧栏拖拽后宽度变化，应平滑更新遮罩，但不要让消息列表做高频重排。

用户截图里的执行流是验收基准：`ToolGroupView` 仍显示「执行了 N 个命令」「使用的 Skills」等紧凑分组、折叠箭头和等宽命令摘要；展开后命令、输出、错误、权限待决与子代理层级一目了然。不得把每个工具改成概念图里的大卡片、合并掉 Skill 标识，或让半透明照片穿透日志。消息、Markdown、代码块、表格横滚、图片、Mermaid、金融图和 OTA 卡也使用各自语义表面，保持复制、链接、选区和搜索命中清楚。

新增的真实用例是「执行了 4 个命令，使用了 2 个工具」：摘要行展开后，先是 `ConversationActivityStrip` 的 `ego-browser` Skill 行，包含运行/完成/失败状态及独立的「查看过程」操作，再是四条终端摘要、`McpTool` 与可能出现的浏览器步骤。长命令必须单行截断且可进入原详情，不能撑宽阅读列；状态与操作始终靠右可达。组头收合只收起子项，Skill 的「查看过程」打开已有的 `BrowserStepsPopover`，弹窗用实色材质和遮罩，关闭后焦点回到触发处。当前源码通过 `hideLinkedBrowserSteps` 把已关联的截图步骤收进 Skill 过程视图；用户截图中仍可见的旧记录/未关联步骤也要有紧凑行样式，迁移不能让这类历史记录消失。此场景同时检查长列表滚动锚点、键盘展开、运行中追加、失败详情和较窄主区，不把工具日志画成漂浮在照片上的文字。

输入框沿用真实附件拖入/粘贴、自动补全、目录/权限/模型选择、Enter/Esc、流式停止和离线恢复；采用高不透明度浮层，避免图像透过文本输入。顶栏、会话信息、右侧能力/文件面板、diff 与文件预览、弹窗和悬浮菜单分别使用内容或浮层材质。右栏收合、持久显示、抽屉、宽度调整及可访问性隐藏逻辑继续由原有布局系统控制。

第一版概念图中值得保留的**身份与操作层**纳入会话设计，但按真实功能落地：在每轮对话起点展示小尺寸用户头像和 Paws 标识，连续工具行不重复头像；头像放在消息边缘，不能侵占 800px 正文宽度或改变虚拟列表的滚动锚点。用户头像可复用现有 `Avatar`/个人资料资源；Paws 使用已有的图标语言。会话页眉宽屏显示分享、星标、更多与右侧面板入口；分享复用现有 `PublicSessionShareDialog` 的确认流程，星标对应现有「置顶会话」而非新建一个独立收藏库。现有消息复制、编辑、分叉等操作继续放在消息附近，悬停/键盘聚焦时出现。窄宽或右栏打开时把次要页眉操作收进更多菜单，避免挤压标题。星标的已置顶状态、分享进行中/失败、只读会话中的可用性都要有明确反馈。

### 4. 颜色、字体与状态

把原始颜色作为来源数据，映射到 Paws 语义 token。`accent` 用于主要操作；`accentAlt`、`highlight` 用于链接、焦点和少量高亮。成功、警告、错误保留各自语义，不直接改成主题蓝。交互表面区分 `surface`、`surfacePressed`、`surfaceSelected`，深色主题下不能残留焦糖主题的暖底。引用原图的暖色只用作克制的装饰。

PC 文本采用现有字体体系：问候语显著、会话正文稳定、标签与辅助说明克制。参考图里的文案和字体不是包资源，不直接复制。正文和占位文字目标对比度至少 4.5:1，识别控件所需边界、图标和键盘焦点至少 3:1；在照片最亮区域和不同裁切下检查，而非只核对静态色值。[WCAG 文字](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) · [WCAG 非文字](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### 5. 所有主内容入口的呈现规则

主题影响 PC Web 的语义颜色，但**照片不是全路由背景**。在实色工具页面上照搬照片会损害代码、表单和资料的可读性。按现有路由和呈现方式处理：

| 入口与真实形态 | 皮肤处理 | 必须保留的交互 |
|---|---|---|
| `/`、`/new`：同一首页组件的两种页眉 | 统一照片工作区、导航材质、实色输入浮层 | 编码/提问、图片模式、深链预设、发送与恢复 |
| `/session/:id`：会话主区 | 响应式照片底层 + 连续实色阅读面 | 虚拟列表、工具组、流式消息、右栏/文件/diff |
| 项目、清单、时间线、归档：左栏模式 | 与工作区照片协调的导航材质；编辑器和整理弹窗实色 | 展开、拖放、标签、编辑、过滤、清单整理 |
| 全局命令面板和 `/session/search` | 实色搜索浮层或搜索页；照片仅在背后被遮罩 | query、筛选、排序、展开、空结果、键盘焦点 |
| `/inbox`、`/settings/*`、`/accounts` 的正常 PC 入口 | 保留原首页/会话作背板，暗色 scrim + 实色桌面 modal | 列表/空态/加载、表单、外观即时切换、返回焦点 |
| 插件市场、`/relationship-advisor`、`/generated-images` | 市场为实色 modal；聊天与图库为实色工作面 | 插件安装入口、聊天流式/错误重试、图库网格/空态 |
| artifacts、Agent 管理、机器、终端、恢复、会话资料/文件/差异、最近会话等工具路由 | 同一深色语义体系的实色工作面；不把照片铺在数据后方 | 各页现有加载/空/错误、表单、diff、文件预览 |
| `/share/:publicId` 访客分享 | 不继承本机 `desktopSkinId` | 按分享快照自己的外观渲染 |

设置桌面 modal 的门槛约 800px，插件市场桌面面板门槛约 900px；800–899px 必须单独核查。直接访问上述 modal 对应路由时遵循其现有导航呈现，不假设背后一定有首页。Tauri 不在支持范围，手机和平板继续使用现有主题与布局。

### 6. 真实 case 与验收矩阵

这些 case 是设计输入，也是后续实现的可见验收范围。每项都要在开启皮肤与关闭皮肤后对照：

| Case | 代表情景 | 验收重点 |
|---|---|---|
| H1 首页默认与 `/new` | 问候、两种会话模式、机器/路径/Agent/权限/模型配置 | 焦点、禁用原因、选择器、发送入口和照片焦点清楚 |
| H2 首页内容拥挤 | 输入增长至 480px、附件、多行长路径、图片风格图库、深链 chips | 小高度可滚动，输入与主要操作不被裁掉；图片和文字不压脸 |
| H3 首页异常 | 离线机器、无有效工作树、创建中、失败重试、草稿/附件恢复 | 恢复动作、状态文案与错误对比度不丢失 |
| S1 会话初始 | 加载、缓存重验证、失败重试、删除/空会话 | 无浅色闪烁；空态和重试按钮仍可见 |
| S2 运行中 | 流式文本、命令/权限待决、停止、离线与恢复 | 状态实时可读，输入与停止动作始终可用 |
| S3 用户红框对应的长会话 | 多个工具/Skills 分组，逐项展开，错误输出，子代理 | 紧凑密度、折叠层级、命令等宽、权限和滚动位置不变 |
| S4 历史与操作 | 分页/锚点/跳最新、只读历史/续接、复制/编辑/分叉、长提示折叠、轮次头像 | 不因材质变化触发列表重排或丢失键盘/鼠标操作；头像不逐行重复 |
| S5 富内容 | Markdown、长代码、横滚表格、图片、Mermaid、金融图、OTA 卡 | 内容表面实色，选区/链接/搜索命中、横滚及图像边界明确 |
| S6 组合工作区 | 左栏固定/悬停/禅、右栏收合/抽屉/拖宽、文件/diff 覆盖层、页眉分享/星标 | 主区宽度始终达现有下限，照片退让；分享进入原确认弹窗，星标与左栏置顶同步 |
| S7 会话输入 | 粘贴/拖入附件、自动补全、配置选择器、长草稿、Enter/Esc | 输入不卡在视口外，焦点与弹层可访问性正常 |
| S8 Skill 与浏览器过程 | 4 条终端、MCP 调用、`ego-browser` 完成状态、查看过程、旧浏览器步骤行 | 组头展开/收合、状态与过程按钮独立可点；长命令截断、弹窗实色、关闭后焦点恢复，历史步骤仍可找到 |
| R1 其他入口 | 搜索、收件箱、设置/外观、插件市场、图库、资料/文件/差异 | 主题色一致，实色阅读面覆盖加载/空/错误/表单 |

视觉对照至少覆盖 2048×1200、1440×900、1100px 宽、800–899px 宽和 720px 高；其中宽屏须在右栏开/关各看一遍，笔记本须拖动左栏到最小/最大。断点取主区的实测宽度，不能仅凭整窗宽度判定照片是否露脸。

## 主题数据与迁移方式

外观设置增加一个完整的 PC 皮肤入口，展示缩略预览和「休闲室内居家」名称。皮肤选择保存为本设备的 `desktopSkinId`，在 PC Web 上优先解析为独立的深色语义主题与场景材质；原有 `themePack`、`themePreference` 和侧栏宽度继续保存，不被皮肤选择覆盖。关闭图片仅改变画布，不改变配色。关闭皮肤后，主题解析回到原有设置。系统明暗变化不打断启用中的深色皮肤；首版明确展示为深色皮肤，不把未经设计的浅色派生版伪装成同一效果。移动端继续读取原有主题设置。

迁移工具是**来源包适配器**，不是通用 CSS 注入器：

1. 校验 ZIP、`manifest.json`、内部文件哈希、相对路径、MIME 与资源大小。
2. 读取 `theme.json` 和图片，保留来源、版本与许可，生成可审阅的标准皮肤配置及资源清单。
3. 按显式映射表输出语义颜色与 PC 材质参数；原包未提供的圆角、间距、状态颜色标记为 Paws 设计值。
4. 报告未识别 CSS 和缺失 token；不执行脚本，不把原站点选择器注入应用。
5. 同版本重复导入得到相同结果。来源包更新时报告差异，由设计评审决定是否改变现有皮肤。

技术上复用 `themePacksData.ts`、`themePacks.ts`、Unistyles、外观设置中的语义主题机制；PC 专属皮肤配置单独描述图片、遮罩、材质和首页构图。PC 主题解析优先于原有主题包，关闭时退回现有解析；`desktopSkinId` 的缺省值为关闭。桌面宽度与折叠继续由现有布局系统管理。

建议把实现边界分成三层，减少对功能逻辑的侵入：

1. **解析层：** 根据 `desktopSkinId` 派生深色语义色、材料参数和照片资源。应用启动时先得到深色回退色，再解码照片，避免浅色闪屏。仅 PC Web 使用，退出皮肤立即恢复原 `themePack` 与 `themePreference`。
2. **工作区层：** `SidebarNavigator` 与 `SidebarView` 提供统一照片画布和半透明导航；`ComposeHome` 在首页透出画布，`SessionView` 在会话主区使用独立固定照片底层及连续阅读面。右栏、文件和 diff 覆盖层保持实色。`(app)/_layout.tsx` 的全局默认表面只做语义深色适配，不把所有路由设为透明。
3. **组件层：** `MessageComposer`、`SessionConfigPanel`、`ToolGroupView`、`ToolView`、Markdown、选择器、`DesktopAppStack` 和设置 modal 消费相同的语义材质与交互状态。只调整视觉容器/颜色/间距，不改工具组结构、消息 key 或发送权限条件。

性能边界：`SidebarNavigator` 现有实现明确避免在拖拽/动画中持续重排会话列表。皮肤切换可动画遮罩与材质，不动画抽屉实际宽度，不把照片重复挂在虚拟列表每一行；图片静态缓存，暗色纯色为首帧。对高耗资源背景模糊给出低性能/减少透明度回退。实现时用现有 `ComposeHome`、`SidebarNavigator`、`useDesktopWorkspaceLayout`、`ConversationTranscript` 测试作为行为回归基础，另补少量跨状态视觉与交互验证。

## 交互与恢复

- 初次选中皮肤：预览、应用，立即可见；选择持续保存在本设备，刷新后不闪回浅色。
- 图片加载失败：回退纯色深灰场景，控件与正文保持可读；不阻断新会话或发送消息。
- 切换明暗：首版皮肤标明「深色」，不自动生成伪浅色；切换回其他 Paws 主题后继续使用其既有明暗偏好。
- 小视口：侧栏按已有规则折叠；照片重新裁切，问候语和输入区完整显示；附件和设置控件允许合理换行。
- 减少动画或透明效果：取消进入动效或使用不透明面板，不改变信息与操作。

## 验收与设计待决点

以上 case 矩阵是最小验收集合。每个视口用相同数据对照旧外观、DreamSkin 参考图和新皮肤，检查照片焦点、信息密度、输入区重心、菜单/弹窗/错误状态，以及鼠标悬停、键盘焦点、选中与按下。功能回归应覆盖拖拽侧栏、工具组展开、历史滚动与分页、附件/发送/停止、右栏、搜索、外观恢复。视觉评审要看真实页面截图和操作过程，不能用概念图替代验收。

正式分发前的主要待决点是**背景图授权**。它影响最终使用哪张图，不影响本设计的构图、材质和主题架构。会话页已选用照片轻微透过阅读面、向右逐渐增强的方向；首轮真实页面评审需以用户红框所示长执行流检验阅读对比度、人物位置和整体氛围，必要时调整透明度参数，无须变成第二套布局。

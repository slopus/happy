# Paws 独立定时任务

状态：实施中。用户在方案交付后继续要求实际完成修改，并创建定时任务验收是否生效；沿用既定方向继续实施，不再逐阶段等待流程确认。该指令不是逐字文档签署，也不代表功能已经完成。

## 目标与范围

用户希望不依赖 Bots，让 Paws 按时间自动执行 AI 工作，例如每天检查关注的 X/Twitter 信息并整理简报。定时触发是通用能力；X 的读取沿用执行机器已有的搜索工具、登录和平台权限，本功能不承诺新增 X 数据接口。

交付一个真实可运行的闭环：创建任务 → 保存 → 关闭 App 仍能到点派发 → 指定机器启动普通会话 → 记录本次真实执行状态 → 从任务历史打开结果。

首版包含创建、编辑、暂停、恢复、删除、立即运行、运行历史；支持一次性、按小时间隔、每天、每周，明确显示时区。支持 Codex 与 Claude；Codex 可以选择该机器实际可用的模型和推理强度，Claude 沿用已配置的默认模型。其他执行引擎不列入首版。

## 约束与已选方向

- 这是 Paws 自身的能力，独立于 Bots，不调用 Bots 的 Routine。
- 使用现有 Node 服务、数据库和机器 Socket 连接，不为每个任务创建系统 cron，不引入新云服务、Redis 队列或 Cloudflare。
- 由服务器根据下次到期时间安排一次性定时器；任务改动、到期、服务器启动和机器重连触发处理。不用固定间隔扫描任务或轮询业务状态。
- 机器须在线且运行支持本功能的新版 daemon。手机或浏览器可关闭；执行机器关机时任务等待，不能把 Paws 描述成提供云电脑。
- 继续使用 Paws 机器加密；服务器不接触任务标题、指令、工作目录、模型配置的明文。
- 普通会话的权限边界保持有效；不默认给予 unattended 任务 bypass/yolo 权限。首版默认只读，用户可显式选择现有普通权限模式；执行中需要批准时显示“需要处理”，从普通会话批准。
- 只在 sibling worktree 开发；根工作区保持干净 main。Web 上线仍经 main CI 发布到 `https://47.115.228.20:8443`。
- Web 和 Android 共用管理功能，按平台提供列表/详情布局；不涉及 Tauri，也不需要新原生模块。手机发布遵循现有 OTA/runtime 契约。

## 方案比较

1. **系统定时器启动 CLI**：单机实现简单，但任务跟随机器而非 Paws 账户，手机管理、离线补偿和多机历史需要另做同步。没有选择此路线。
2. **Paws 服务持久化调度、daemon 执行**：复用现有账户、加密、会话和通知，执行记录能在各端查看；需要处理重启恢复、重复投递和机器离线。沿用本轮已选定的方向。
3. **接入完整工作流平台**：具有丰富队列能力，但增加部署、权限、数据和维护负担，对当前通用定时会话需求过重。

具体存储、UI 组件、错误码、文件拆分和测试方式由实施者决定，不要求用户选择技术细节。

## 管理界面

以本轮三张 ChatGPT 截图作为信息结构参考，保留 Paws 现有导航、主题和会话交互。

- 增加时钟图标的“定时任务”入口。PC 使用任务列表＋详情两栏；手机从列表进入详情，保留清晰返回入口。
- 列表包含“新建任务”、搜索与全部/已开启/已暂停筛选；任务行显示名称、下次运行时间、重复规则、执行机器及最近状态。
- 首次空态提供“每日资讯简报”“关注账号更新”“每周项目回顾”等示例，点击只填入草稿，不自动创建或运行。
- 创建/编辑表面先显示名称、指令、重复和时间；高级项包含机器、已有工作目录、引擎、模型/推理强度、通知、权限以及“每次运行开启新聊天”。
- 机器选择明确显示在线与功能支持状态。保存可以选离线但已支持的机器，详情提示等待其上线；旧 daemon 显示需升级，不以点击成功冒充可执行。
- 显示浏览器/手机当前 IANA 时区，可改为合法 IANA 时区；保存后跨设备仍沿用任务原时区。每日/每周按该时区的本地时间触发，按小时间隔按绝对时间计算。
- 保存验证错误原位提示，失败保留草稿；关闭未保存草稿需防止误丢失；下拉、键盘和外点关闭复用项目浮层规范。
- 详情显示下一次运行、配置和历史；每次历史包含计划时间、实际开始/结束时间、状态、跳过/失败原因和会话入口。结果正文仍在普通 Paws 会话中查看，避免再造消息渲染器。
- 所有文案使用 i18n，所有颜色和交互态取当前主题语义 token。覆盖非默认深色主题和窄屏触控。

## 调度与时间语义

- 一次性任务必须指定未来时间；触发产生运行记录后自动结束该次计划，历史保留。立即运行不消耗未来的一次性计划。
- 间隔为整数小时，最小 1 小时；每天为一组 `HH:mm + timezone`；每周增加星期选择，可选多个星期，至少一个。
- 默认沿用当前时区，默认每天 09:00；默认值是实施者建议，不是用户已确认的个人偏好。
- 夏令时：不存在的本地时间跳过当日；重复出现的时间当天仅执行一次。测试覆盖两种转换，界面展示最终下一次时间。
- 一个任务最多一个仍可能执行的运行。运行中、等待批准和执行结果不确定都会占用任务，后续到期只记录为“跳过：上次仍在执行或待处理”，不并行启动；下一次计划继续向前推进。
- 离线时只保留一个待执行运行。重连后执行合并后的待办，并在历史注明错过的时间段；不补跑每一个历史时间点。
- 暂停阻止未来派发，并取消尚未领取的待执行运行；已启动的会话继续，停止仍使用普通会话的停止操作。删除采用同样规则，不能误杀用户其他会话。
- 编辑使用版本检查；过期编辑返回冲突，不覆盖另一个设备的新配置。配置变更只影响后续运行，已有运行保留当时的配置快照。
- 立即运行使用请求 ID 去重；任务暂停时也允许用户显式立即运行。运行中再次点击显示已有运行，不能产生重复启动。

## 数据与安全边界

首版复用数据库现有 `UserKVStore` 的服务器保留命名空间，分别保存计划记录与运行记录，而非修改数据库 schema。该选择避免违反仓库“数据库迁移只能由人执行”的约束，不增加一次手工迁移依赖。

- 保留前缀 `paws:scheduled:v1:`，通用 KV 写入口不得修改该前缀；计划和运行由专用、严格校验的 API 管理。
- 计划公开字段：随机任务 ID、所属账户、目标机器、时间规则/时区、启停、版本、下一次时间、时间戳、非敏感通知策略；私密字段为机器加密的配置密文。
- 运行公开字段：运行 ID、任务 ID、目标机器、原计划时间、状态、领取标识、会话 ID、时间戳、固定错误码；配置和错误详情使用机器加密的快照。
- 每个账户最多 100 个计划；每个任务保留最近 100 次终态历史，另保留全部仍可能执行/阻塞中的运行。新增历史时只清理已终态的超限记录，不能因连续跳过而删除仍在执行的旧记录；不启动周期清理扫描。
- 账户归属与机器归属每次由服务器验证，客户端不可自行指定另一个账户；终态上报绑定正确的运行、机器和会话。所有查询、修改和派发都按账户隔离。
- 记录更新使用数据库 compare-and-swap/version 与事务。到期推进和创建运行原子提交，重启不会丢失计划，也不因两个计时器同时到期创建两次运行。
- 单服务实例是本次部署验收范围；重复到期/领取仍须由数据库唯一键与版本阻挡。若未实现跨实例变更通知，不宣称支持多实例调度。
- 服务器启动只恢复一次已保存计划及未终结运行，之后由已知截止时间和事件驱动。启动时读取保留前缀不会读取或解密普通用户 KV。

## 派发、执行与恢复

运行状态：`pending → claimed → running → completed | failed | cancelled`；`waiting-for-input` 和 `uncertain` 是阻塞状态，界面统一提示“需要处理”，不会释放任务的执行占用。只有本次根 turn 明确结束才能记为 completed；只有确认未投递或根 turn 已终止才能正常失败/取消并释放占用。单独的 skipped 历史不会占用任务。

1. 到期事务保存运行及配置快照、推进下一次时间，然后通知目标机器。暂时离线不会丢掉 pending 记录。
2. daemon 在收到“有待执行任务”的 Socket 事件、连接成功时分别进行一次领取请求。它只领取自己的待执行记录，运行 ID 作为幂等键。
3. daemon 解密并校验配置，确认工作目录存在、引擎可用、模型和账户有效；不为了无人值守任务默默创建任意目录或换成其他账户。
4. 启动前写入本机原子 journal，保存运行与会话绑定及加密材料引用。任务专用会话的绑定和密钥使用受保护的长期存储，不能只依赖现有会被 14 天清理的普通会话缓存，也不能用相同 tag 重新生成密钥。复用现有 Codex grant、spawn/resume 和加密消息投递路径；用户提示使用稳定 localId `scheduled:<runId>`，重试同一次投递不会重复添加提示。
5. “每次新聊天”开启时，每次运行创建独立会话；关闭时为该任务维护一个专用会话，后续恢复同一会话。不能向用户正在使用的任意聊天注入消息。会话归档、丢失或当前有人操作时明确需要处理，不静默另开或争抢。已有固定会话时更换机器/引擎必须显式选择重置绑定并新开会话，无法解密旧绑定时不得猜测或复用错误密钥。
6. 运行完成必须关联此提示被接受的 localId 与根 turn；会话启动、idle、其他 turn 完成、子 agent 完成均不能作为本次成功证据。失败/权限请求和退出事件同样关联本次运行。
7. journal 在服务端确认前保留终态回执。网络重连只补交同一回执，不重新执行；daemon 重启恢复已知绑定。遇到“可能已经执行，但无法证明”的崩溃窗口，标记 uncertain 并继续阻止后续运行，不以自动重发获得表面成功。
8. 为运行设置一次性的最长等待截止时间（默认 24 小时）。到时缺少可靠结果记为 uncertain，不能记为成功或自动再次执行；不强杀既有会话。没有业务状态查询循环。
9. 需要批准时可以进入原会话处理，处理后继续跟踪同一次根 turn。结果不确定时可进入原会话确认并停止；确认终止后释放占用。若绑定本身丢失，用户可在任务详情显式“结束跟踪”后重新运行，操作前解释旧执行可能仍在继续；这属于用户主动处置，不作为系统保证旧执行已停止的证据。旧 turn 的迟到回执只能更新其原运行，不能覆盖后续运行。

通知提供“每次完成 / 重要更新 / 不通知”。默认“重要更新”，其含义在首版固定为执行失败或需要人工处理，不声称 AI 已实现任意内容价值判断；常规成功仍可在历史查看。复用现有通知链路并抑制同一次运行的重复完成提示，不让服务器看到私密标题/正文。

## 实施顺序与验收

在本文通过审阅后编写具体实施计划，按以下依赖顺序实施；每步的实现细节由当前会话负责。

1. 共享时间规则/状态协议及有意义的失败测试：时区、DST、一次性、间隔、去重、暂停与重叠。
2. 专用持久化 API、保留 KV 命名空间、截止时间调度、启动恢复、Socket 通知与权限隔离。
3. daemon 执行器、durable journal、稳定提示、精确结果关联、离线及崩溃恢复。
4. 各端导航、任务列表/创建/详情、动态模型选择和全语言翻译。
5. 独立代码审查、适用测试与 typecheck；生产环境最小 E2E、交互评审和已通过路径的媒体证据；随后按既有 PR/CI 授权正常交付。

| Case | 可观察的通过标准 |
|---|---|
| ST-01 创建与持久化 | 从定时任务入口保存一条未来任务，刷新/重开仍存在；错误输入不丢草稿 |
| ST-02 无前台触发 | 关闭管理页面后到点，指定机器产生一条真正的 AI 回复；历史链接能打开对应结果 |
| ST-03 管理 | 编辑、暂停/恢复、搜索筛选、删除有效，其他设备刷新/事件后显示一致 |
| ST-04 幂等与并发 | 重复到期/领取/投递/立即运行不产生重复 AI 执行；上次仍运行时按规则跳过 |
| ST-05 离线与恢复 | 机器离线不丢任务，上线只补一次；服务/daemon 重启恢复或明确需要处理，不假报成功 |
| ST-06 配置与权限 | 可用模型/强度生效；无效账户/目录失败可见；需要批准时可从会话处理，默认不绕过 |
| ST-07 会话复用 | 两次运行分别证明新会话开关开/关的行为，绑定不因重启混淆 |
| ST-08 时间 | 每日/多星期/间隔和跨时区的下一次时间正确，DST 两个边界通过自动测试 |
| ST-09 隔离与加密 | 越权操作被拒绝；数据库/API 不含私密配置明文；通用 KV 无法绕过专用规则 |
| ST-10 跨端可用 | 正式 Web 和可访问的 Android 环境可完成核心操作，非默认深色主题、窄屏和草稿关闭正常 |

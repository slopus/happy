# Paws 多账号切换 v1

## 使用

侧栏底部头像是日常入口：点击直接显示保存的账号，当前账号打勾，点击其他账号切换。菜单内的“添加账号”打开 `/accounts?add=1` 表单；账号管理页面默认只显示列表和添加入口，不常驻展示密钥输入框。取消添加会清空已输入的密钥和名称。

每个账号需要自己的服务地址与恢复字符串；添加过程向指定服务验证身份，不把恢复字符串写入 URL、日志或元数据。原有单账号会自动迁移，保留原草稿、设置与缓存。菜单展开和表单尺寸变化使用减少动态效果设置兼容的过渡；动画完成及列表加载后聚焦首个账号，菜单整体按视口限高并统一滚动。

点击账号后重新加载 Paws。一次只激活一个账号，不合并不同账号的机器或会话列表。切换保留凭据及文字草稿；未发送附件只在内存中，主动切换前会提示重新选择。浏览器其他标签页跟随切换并重载，不能继续用旧页面发送新账号请求。其他标签页的未发送附件仍可能因重载丢失。

移除非活跃账号会删除其登录凭据；历史本地缓存仍留在该账号的隔离空间，重新添加同一账号可恢复。退出当前账号会清理当前账号本地状态及登录凭据，不退出其他保存的账号。切换失败显示重试和返回账号管理；原生重载失败时保持冻结，不原地替换运行中的同步单例。

启动时发现活跃凭据损坏，也可通过错误页的账号管理入口恢复：只解除当前选择并重载，不删除保存的账号与数据，且不会再次迁移残留旧凭据。随后选择健康账号，或重新添加原账号来修复凭据。

## MISS 跳转契约

使用 `/accounts?accountId=...&serverUrl=...&sessionId=...`，三个值均通过 URLSearchParams 编码。

- `accountId` 是 MISS 专用 Paws 账号的服务端身份，不是 MISS 网站的登录用户 ID。
- `serverUrl` 是该账号实际使用的 Paws relay origin；不同 origin 不自动视作同一服务。
- `sessionId` 是实际 Paws 会话 ID，不是 MISS 的讨论编号。
- 不携带凭据，也不因打开链接自动切换。页面展示目标，用户选择已保存的匹配账号或添加该账号后再点击打开。
- 首次添加 MISS 专用账号仍需要其恢复字符串。MISS 登录权限并不自动授予 Paws 专用账号权限；该账号可能能查看服务账号下所有会话，不应向普通受邀学习者分发。

`sources/auth/accountLink.ts` 提供 URL 生成与校验实现。此分支未改动 MISS 的生产链接；需等 Paws Web 合并发布成功后，再更新 MISS 链接，避免先发布跳到尚不存在的路由。

## 故障与隔离

账号身份由规范化服务 origin + account ID 定位。Native 凭据保存在 SecureStore，Web 延续本地 localStorage 凭据存储方式。元数据与凭据分开；每个账号的 MMKV 存储空间、草稿、设置、会话缓存与待同步队列隔离。

账号切换冻结请求、关闭旧 socket/文本流，再提交活跃账号指针并重载。generation 阻止旧标签读取新凭据；Web Locks 串行化注册表操作。旧标签退出通过 generation 比较，不清除另一标签的新账号。

推送注销最多等待一次 3 秒请求。失败会保留清理任务和单独保存的 JWT（不保留恢复密钥），后续启动、前台切回及每分钟检查到期任务，指数退避至每小时、每轮最多 3 项。网络恢复并清理成功前仍可能收到旧账号通知；通知点击会先验证当前账号能访问目标会话。重新激活原账号会取消它的旧清理任务。服务器永久拒绝清理 JWT 时仍需服务端处理；本客户端不声称离线时可立即撤销服务端绑定。

## 验证边界

自动化覆盖账号添加/移除、A→B→A、迁移中断、坏元数据、错误账号链接、冻结请求、草稿保存、旧标签退出、推送超时/500及队列公平性。真实个人/MISS账号切换与原生设备重载仍需要使用者验收，不读取或复制现有真实恢复密钥进行测试。

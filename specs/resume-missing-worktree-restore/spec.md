# resume-missing-worktree-restore

## 배경

2026-10-01: 세션 A 가 `.aplus/worktrees/eager-lynx` 에서 일하다가 "워크트리 정리" 요청을 받고
자기 작업 폴더인 그 워크트리와 브랜치를 직접 지웠다. 6시간 뒤 idle 로 세션 프로세스가 종료됐고,
다음 메시지에서 데몬 resume 은 `ENOENT ... realpath '<워크트리 경로>'` 로 실패했다. 웹의
"새 대화로 이어가기"도 지워진 경로를 그대로 써서 같은 상태였다.

이 문제가 생긴 경로는 하나만이 아니다. Desktop 자동 정리는 결정에 따라 쉬고 있는(standby) 대화의
워크트리를 7일 뒤 지우고 브랜치는 남긴다(aplus-dev-studio-desktop
`specs/desktop-worktree-cleanup-reliability` context 2026-08-10 결정). 그 결정은 워크트리를 다시
만들 수 있다고 전제했지만, 다시 만드는 쪽은 구현되지 않았다.

## 요구사항

- R1. Given 세션 작업 폴더가 `<repo>/.aplus/worktrees/` 아래에 있고 사라졌으며 `<repo>` 가 git
  체크아웃일 때, When 데몬이 그 세션을 resume 하면, Then **같은 경로**에 워크트리를 다시 만든 뒤
  resume 한다. 경로가 같아야 경로 기준으로 저장된 에이전트 대화 기록이 그대로 이어진다.
- R2. 브랜치는 이 순서로 고른다: 에이전트 대화 기록의 마지막 브랜치(Claude `gitBranch`)가 로컬에
  있으면 그 브랜치 → 워크트리 폴더 이름과 같은 로컬 브랜치 → 기록의 브랜치 이름으로 메인 체크아웃
  HEAD 에서 새로 만듦 → 이름이 없으면 메인 체크아웃 HEAD 에 detached.
- R3. 남은 브랜치가 다른 워크트리에 체크아웃돼 있으면 강제로 가져오지 않고 실패한다(기존 오류 흐름 유지).
- R4. 관리 경로 밖(`.aplus/worktrees` 아님)의 사라진 폴더는 건드리지 않는다.
- R5. 세션 작업 폴더가 워크트리의 하위 폴더였다면 재생성 후 그 하위 폴더가 있어야 하며, 없으면 방금
  만든 워크트리를 되돌리고 실패한다.

## 범위 밖

- Codex 대화 기록에서 브랜치 읽기 — 지금은 폴더 이름과 같은 브랜치로만 찾는다.
- 웹 "새 대화로 이어가기"가 지워진 경로를 쓰는 문제 — 데몬 resume 이 복구하면 그 경로로 가지 않는다.
  resume 자체가 실패하는 경우의 개선은 별도 작업.

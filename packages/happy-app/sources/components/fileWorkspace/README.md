# File workspace history

PC Web keeps the approved chat/files shell. `VersionController` owns current artifact reads, paginated versions, an independently selected immutable preview, and durable operation IDs. `FileWorkspaceController` continues to own drafts and entry hashes. Viewing history never edits the file controller.

正文首先通过工作区文件接口读取，整次请求（含加解密）的等待上限为 10 秒。读取成功后才在后台获取版本信息；版本服务不可用不会阻塞正文或延迟文件不存在的提示。只有入口哈希与当前正文一致且无待处理操作时，才使用版本预览和版本引用。已有草稿、写入哈希检查和服务端托管文件保存规则保持有效。相对路径始终以会话工作目录为基准，不搜索其他项目或绕过工作区边界。

Registration requires an explicit entry/dependency list relative to the authorized session workspace. Only those paths are versioned. Discovery resolves the session root canonically at the machine API boundary. Managed saves use `artifactSave`; following chat references carry the artifact identity and whole-manifest expected revision in addition to the entry hash. Restoring appends a version and rebinds context only after a successful matching file read. Dirty file drafts block restore; unsent chat remains mounted.

HTML and Markdown previews share immutable `readRef` resource access. Missing historical files never fall back to working paths. HTML keeps its existing static sandbox and explicit interaction switch. Read-only Markdown defaults to inert images/cards; only a caller-supplied frozen image map opts images in. Closing/replacing a read revokes its object URLs.

Mutations never retry automatically. Unknown results retain scoped operation IDs across reload; a user status check can inspect the operation and explicitly resolve advertised recovery actions against the observed revision. Machine events, reconnect and user actions refresh once; there are no periodic business queries.

## Markdown passage annotations

In the current saved Markdown preview, enable **标注 / Annotate** in the file toolbar and click a paragraph, heading, list or table. Hover outlines identify the target; keyboard users can focus a target and press Enter. Drag-selecting specific text also remains available outside marking mode. The comment editor is a single-line capsule anchored above the selected passage where space permits. It has no visible title, path, close icon, quoted-text block or textarea. Press Enter or the round check button to save; click outside or press Escape to dismiss. IME composition does not submit. A new annotation is persisted atomically with its nonempty comment; dismissal leaves no empty mark.

Saved annotations leave numbered markers near the end of the selected text. Hover, focus or click a marker to reveal its plain-text comment bubble; click the bubble to edit. The conversation composer shows an annotation count; hover, focus or click it to open a compact preview above the count, with a small text thumbnail, selected-text label, comment and edit/delete icons. Clicking a preview locates its passage and restores preview mode when necessary. File annotations no longer open a dedicated sidebar. Capsule, marker, bubble and preview interactions use subtle hover scaling and respect reduced-motion preferences. Hash changes, unsaved file drafts and failed rendered anchors prevent a guessed relocation. The existing message annotation flow stays separate. All pending annotations can be submitted together with optional general instructions. Save file drafts before annotating; historical previews retain their existing behavior.

Each annotation retains the file path, baseline hash, optional artifact identity, rendered offsets, nearby text and comment. Highlights bind to path plus content hash, so later artifact discovery keeps existing highlights while changed content cannot inherit them. Rendered offsets are never treated as Markdown source offsets. The model receives revision context and instructions to reread the file and report ambiguous passages; this is guidance, not an automatic patch operation.

Pending annotations persist in the account/session draft store. Queue acceptance clears only submitted revisions. The durable staged message retains the editable annotation snapshot and original free text separately from the readable display text and model context. Failed or queued messages can restore the snapshot without overwriting newer annotations. The point-pick wrappers use React Native Web dataSet forwarding, which must be checked in the actual DOM rather than only React test doubles. Browser visual/E2E verification and deployment are separate from the focused component/runtime tests.

# Feature inventory

Everything happy-app does on an iPhone, as a checklist for this port. Built
from `packages/happy-app/sources/app/(app)` (routes) and
`sources/components`. Tick an item only when it is merged on the
integration branch with its layout tests.

Owners are workstreams (see AGENTS.md, "Workstreams"). `[x]` done, `[~]`
partly done, `[ ]` not started.

  - Diff rows are syntax-coloured with Prism, as `components/diff/syntax/*` does: `scripts/generate-prism-grammars.cjs` writes highlight.ts's 45 grammars from prismjs (patterns rewritten for ICU with JavaScript's meaning), and `HappyCore/Diff/Syntax` ports `Prism.tokenize`, highlightLines, tokenize.ts, plan.ts and code.ts.   - Rows are drawn only near the screen instead of being mounted in batches (`useProgressiveRows`), so a long file is full height from the first frame rather than growing over a few frames.
  - The file viewer (`Screens/SessionFileScreen.swift`, routed from `.sessionFile`) reads the file and its `git diff`, keeps the last read per session for revisits in the account's own cache (`AccountSession.fileCache`; another account never sees it), and shows the diff (DiffDisplay) or the syntax-coloured text (SimpleSyntaxHighlighter's tokenizer and colours). Lines are measured off the main thread and drawn only near the screen; the one Text block in happy-app wraps each line the same way. A long press on the text offers Copy for the whole file, as RN's selectable Text does (plain text only; RN also puts RTF on the pasteboard). A CRLF line's carriage return is left off the drawn text; alone at the end of a DiffDisplay row's Text, RN may measure it as an extra empty line (unverified). The route carries no line or column, as no happy-app caller passes one, but the screen takes them and scrolls as file.tsx does. The session's root is read off the main thread; until then the file resolves against the root it had when one of its files was last shown, so a revisit still draws its cached copy at once. `SessionFileCache` can also keep each read in the account's own directory (`SessionFileCache(directory:)`): the 256 most recently used reads, 64 MiB at most, none over 4 MiB, under names that are hashes of the session and path; in memory the 32 most recently used, 8 MiB at most. A copy on disk is read off the main thread, once however many ask, before the computer is; nothing is fetched to fill the cache. `close()` stops every read and write before an account's directory is removed, and `removeSession` drops a deleted session's reads. Deviation: when a refresh fails while a kept copy shows, the copy stays on screen under the error alert; file.tsx shows the error instead (it keeps nothing across launches, so offline it has nothing to show). The cache never makes its directory: it is made off the main thread as the account starts (`SessionFileCache.prepare`), and without it nothing is written, so a signed-out account's directory is never made again. Not yet: the account makes that directory, hands it to its cache, closes the cache when it stops and before its directory is removed, and drops a deleted session's reads (`AccountSession`, `AccountController`); until then the cache is in memory only, as happy-app's is.
